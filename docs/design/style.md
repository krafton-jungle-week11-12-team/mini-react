# 화면 스타일 설계 (Double D)

- 상태: 리뷰 중
- 작성자: 임동호
- 관련 이슈: #12

## 개요

검증 페이지 Double D의 생김새를 정해요. 이 문서를 읽으면 배치, 색, 글자, 렌더링 결과 박스의 규칙을 알고 `index.html`과 CSS를 만들 수 있어요. 페이지가 어떤 순서로 모듈을 부르는지는 [검증 페이지 설계](page.md)에서 다뤄요. 디자인 초안은 [Design 캔버스 - Double D 검증 페이지](https://claude.ai/artifact/C46shqPNgankoVTQTkpf7f)에 있어요.

## 위치와 흐름

```text
index.html + style.css ──▶ 화면 (검증 페이지가 요소 노드를 찾아 씀)
```

- 입력을 주는 곳: 없음. 정적인 HTML과 CSS예요.
- 출력을 받는 곳: [검증 페이지](page.md)의 `PageElements`. 이 문서의 요소 노드 `id`로 찾아요.
- 스크롤 맞추기만 검증 페이지의 `createPage`가 이벤트로 연결해요(동작 방식 참고).

## 자료구조

색과 글꼴은 CSS 변수로 둬요.

```css
:root {
  --dd-red: #E03131;      /* 실제 영역 */
  --dd-blue: #1971C2;     /* 테스트 영역 */
  --dd-primary: #6B46F5;  /* 바뀐 것 */
  --dd-bg: #F6F7FF;
  --dd-card: #FFFFFF;
  --dd-text: #14162E;
  --dd-error: #E03131;
}
```

| 변수           | 값                                                                   | 쓰는 곳                                                    |
| -------------- | -------------------------------------------------------------------- | ---------------------------------------------------------- |
| `--dd-red`     | `#E03131` (띠 `#FF4D4D`, 연한 테두리 `#FFC9C9`, 옅은 배경 `#FFEEEE`) | 실제 영역 제목·띠·코드 칸 테두리, 앞으로 버튼(켜짐)        |
| `--dd-blue`    | `#1971C2` (띠 `#2B8FFF`, 연한 테두리 `#A5D8FF`, 옅은 배경 `#EAF4FF`) | 테스트 영역 제목·띠·입력창 테두리, 뒤로 버튼(켜짐)         |
| `--dd-primary` | `#6B46F5` (글자 `#5330D9`, 옅은 배경 `#EDE7FF`)                      | 바뀐 것: 강조 표시, Diff 요약, 현재 기록, Patch 버튼(켜짐) |
| `--dd-bg`      | `#F6F7FF`                                                            | 페이지 배경                                                |
| `--dd-card`    | `#FFFFFF`, 테두리 `#DCE0F5`                                          | 패널                                                       |
| `--dd-text`    | `#14162E`, 보조 `#565C7A`                                            | 글자                                                       |
| `--dd-error`   | `--dd-red`와 같아요                                                  | 오류 문구                                                  |

- 로고는 빨강 D와 파랑 D가 겹치고, 겹친 부분이 보라색이에요. 이전(실제 영역)과 새 것(테스트 영역)을 겹쳐 다른 곳을 찾는다는 뜻이에요. 파일은 `public/dd-logo.svg`예요.

## 동작 방식

### 배치

```text
┌──────────────────────────────────────────────────────────────────────────┐
│ [로고] Double D                    [ 뒤로 | 기록 2 / 2 | 앞으로 ] [ Patch ] │
│                                                                          │
│ ┌ 실제 영역 (빨강 띠) ────────────┐   ┌ 테스트 영역 (파랑 띠) ──────────┐  │
│ │ <pre> HTML 코드 (줄 번호)      │   │ <textarea> HTML 코드           │  │
│ │ realRoot 렌더링 결과           │   │ testRoot 렌더링 결과           │  │
│ └────────────────────────────────┘   └────────────────────────────────┘  │
│                                                                          │
│ ┌ Virtual DOM ────┐   ┌ Diff ─────────────────┐   ┌ 기록 ─────────────┐  │
│ │ 현재 기록의       │   │ 요약 문구              │   │ ○ 기록 1          │  │
│ │ Virtual DOM 트리  │   │ 변경 목록              │   │ ● 기록 2 (지금)   │  │
│ └─────────────────┘   └───────────────────────┘   └──────────────────┘  │
└──────────────────────────────────────────────────────────────────────────┘
```

- 페이지 전체는 한 화면(브라우저 창 높이)에 다 들어가요. 페이지 전체 스크롤은 없어요.
- 머리글 아래를 위 줄(두 영역)과 아래 줄(세 패널)이 3:2로 나눠요. 각 칸의 내용이 넘치면 그 칸 안에서만 스크롤해요.
- 좁은 화면(768px 미만)에서는 예외로 패널을 쌓고 페이지 전체를 스크롤해요.

| 구역        | 들어가는 요소 노드                              | 규칙                                                                                                                                                                                                                                       |
| ----------- | ----------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 머리글      | 로고, 이름, 뒤로, `historyLabel`, 앞으로, Patch | 왼쪽에 로고와 이름, 오른쪽에 버튼을 모아요. 뒤로·`historyLabel`·앞으로는 한 덩어리로 붙이고 Patch는 따로 둬요. `historyLabel`은 "기록 (현재 위치 + 1) / (기록 개수)"예요                                                                   |
| 위 왼쪽     | `realCode`, `realRoot`                          | 실제 영역. 위쪽 띠와 제목은 빨강, 코드 칸 테두리는 연한 빨강이에요. 코드 칸 왼쪽 줄 번호 칸(`realLines`)에 줄 번호를 보여 줘요. 바뀐 줄은 칠하지 않아요. 바뀐 곳은 렌더링 결과의 강조 표시로만 보여 줘요([검증 페이지](page.md#설계-결정)) |
| 위 오른쪽   | `testCode`, `testRoot`                          | 테스트 영역. 위쪽 띠와 제목은 파랑, 입력창 테두리는 연한 파랑이에요. 입력창 왼쪽에도 줄 번호 칸(`testLines`)을 둬요. 실제 영역과 너비가 같고 나란히 놓여요(FR-W01)                                                                         |
| 아래 왼쪽   | `vdomView`                                      | 현재 위치 기록의 `vdom`을 트리로 보여 줘요(FR-X03). 태그는 파랑, 공백·줄바꿈 텍스트는 흐린 회색이에요                                                                                                                                      |
| 아래 가운데 | `message`, `diffView`                           | 요약 문구와 마지막 Patch의 변경 목록이에요(FR-W30, FR-X04). 화면에 안 보이는 변경은 점선 칩과 흐린 글자로 구분해요. 오류 문구는 빨강이에요                                                                                                 |
| 아래 오른쪽 | `historyView`                                   | 기록 목록을 세로 타임라인으로 보여 줘요(FR-X01). 현재 위치 기록은 보라색 점과 보라색 글자예요. 눌러서 이동하는 기능(FR-X02)은 없어요                                                                                                       |

### 글자

| 구분                              | 글꼴           | 크기               |
| --------------------------------- | -------------- | ------------------ |
| 페이지 이름                       | Pretendard 800 | 27px               |
| 패널 제목 (다섯 패널 모두)        | Pretendard 800 | 20px               |
| 내용 (Diff 목록, 기록 항목, 버튼) | Pretendard     | 14px               |
| 보조 글자                         | Pretendard     | 13px               |
| HTML 코드, Virtual DOM 트리       | JetBrains Mono | 13px, 줄 높이 22px |

- Pretendard는 `public/fonts/PretendardVariable.woff2`를 `@font-face`로 불러요(가변 글꼴, 굵기 100~900). 라이선스는 같은 폴더의 `Pretendard-LICENSE.txt`(SIL OFL 1.1)예요.
- JetBrains Mono는 Google Fonts에서 불러요. 불러오지 못하면 브라우저의 고정폭 글꼴(`monospace`)로 보여요. 코드 칸과 트리는 글자 너비만 같으면 되므로 괜찮아요.

### 코드 칸

- 실제 영역 코드 칸(`realCode`)과 테스트 영역 입력창(`testCode`)은 높이가 같아요. 영역 패널 안에서 렌더링 결과 박스와 남은 높이를 반씩 나눠요. 안쪽 여백 위아래 6px, 테두리 2px로 맞춰 두 영역의 렌더링 결과 박스가 같은 높이에서 시작해요.
- 줄 번호 칸은 코드 칸 테두리 안 왼쪽에 붙여요. 너비 40px, 오른쪽 정렬, 오른쪽 여백 12px, 글자색 `#9AA0AE`이고 글꼴과 줄 높이는 코드와 같아요(JetBrains Mono 13px, 22px). 스크롤바는 숨기고(`overflow: hidden`) 코드 칸의 `scrollTop`을 따라가요. 그래서 두 영역의 코드가 같은 가로 위치에서 시작해요.
- 입력창의 크기 조절 손잡이는 꺼요(`resize: none`). 칸보다 길면 칸 안에서 스크롤해요.

### 렌더링 결과 박스

- `realRoot`와 `testRoot`에는 **똑같은** CSS만 걸어요. 한쪽에만 거는 CSS는 두지 않아요. 같은 CSS를 받으므로 두 영역의 렌더링 결과는 같게 보이고, 비교(FR-W06, W15)에 영향이 없어요.
- 두 박스에 거는 CSS: 글꼴 Pretendard, 글자색 `--dd-text`, `h1` 20px, `li` 14px, 안쪽 여백 위아래 16px·좌우 20px, 넘치면 `overflow: auto`예요. 높이는 영역 패널 안에서 코드 칸과 남은 높이를 반씩 나눠요.

### 스크롤 맞추기

- 두 렌더링 결과 박스는 스크롤을 함께 움직여요. 한쪽에서 `scroll` 이벤트가 나면 다른 쪽의 `scrollTop`, `scrollLeft`를 같은 값으로 맞춰요. 맞추는 중에 생긴 `scroll` 이벤트는 무시해 서로 계속 부르지 않게 해요.
- 두 코드 칸(`realCode`, `testCode`)도 같은 방법으로 함께 움직여요.
- 스크롤 위치는 DOM 트리를 바꾸지 않아 Virtual DOM 변환과 비교에 영향이 없어요.

### 강조 표시 모양

- 강조 표시는 옅은 보라(`#EDE7FF`) 배경 띠예요. 글자 위치가 움직이지 않게 여백 대신 `box-shadow: 0 0 0 4px`로 띠를 넓혀요.
- 박스 안쪽 여백이 4px보다 넓어서 가장자리 요소 노드의 띠도 잘리지 않아요. 영역 컨테이너 자체(`parentNewPath`가 `[]`)를 강조하면 박스 배경 전체가 보라가 되고, 바깥 4px 띠는 박스 밖이라 보이지 않을 수 있어요. 배경만으로 충분히 보여요. 스크롤로 박스 밖에 나가 있는 요소 노드의 띠는 다른 내용처럼 잘려요.
- 띠는 0.4초 동안 투명에서 보라로 나타나고(`ease-out`), 그 뒤 다음 Patch나 기록 이동 전까지 그대로 남아요. `animate()`의 `fill: 'forwards'`로 마지막 모양을 유지해요. 그래야 무엇이 바뀌었는지 천천히 볼 수 있어요.
  ```ts
  el.animate([off, on], { duration: 400, easing: 'ease-out', fill: 'forwards' });
  // on  = { backgroundColor: '#EDE7FF', boxShadow: '0 0 0 4px #EDE7FF' }
  // off = 같은 색, 투명도 0
  ```
- 이 함수는 `src/main.ts`에 두고 `createPage`의 `options.highlight`로 넘겨요. 지우는 일은 [검증 페이지](page.md#patch)가 해요(다음 Patch, 기록 이동, 오류 처리 때 실제 영역의 애니메이션을 모두 취소).
- [변경 표시](change-highlight.md)의 `options.highlight`에 이 모양을 `element.animate()`로 그리는 함수를 넘겨요. 스타일 속성을 바꾸지 않아 두 영역 비교에 영향이 없어요(FR-W27).

### 변경 종류 라벨

- 강조 표시한 요소 노드 옆에 변경 종류(`text`, `create`, `remove`, `replace`, `props`)를 Diff 결과 패널과 같은 칩으로 띄워요. 한 요소 노드에 여러 종류가 있으면 칩을 나란히 놓아요.
- 놓는 자리:
  - 글자만 가진 요소 노드(`h1`, `li` 등): 글자 마지막 줄 끝에서 8px 오른쪽, 그 줄 가운데 높이
  - 자식 요소 노드가 있는 요소 노드(`ul` 등): 그 요소 노드의 오른쪽 위 안쪽. 자식의 라벨과 겹치지 않아요
  - 영역 컨테이너 자체: 렌더링 결과 박스의 오른쪽 위 구석
- 칩은 글자 11px, 위아래 1px·좌우 6px 여백에 옅은 그림자를 넣어 강조 띠 위에서도 보여요.
- 라벨은 `realRoot` 안이 아니라 형제인 층(`realMarks`, `position: absolute`, `pointer-events: none`)에 그려요. 실제 영역의 DOM을 바꾸지 않아 두 영역 비교에 영향이 없어요(FR-W27). 박스 밖으로 스크롤된 라벨은 층의 `overflow: hidden`으로 잘려요.

### 버튼 상태

- 켜지면 각자 색이에요. 뒤로는 옅은 파랑 배경 + 진한 파랑 글자, 앞으로는 옅은 빨강 배경 + 진한 빨강 글자, Patch는 보라예요.
- 꺼지면 세 버튼 모두 회색 배경 `#F2F3F7`, 회색 글자 `#A3A8B8`, `cursor: not-allowed`예요.

### 좁은 화면

- 화면이 768px 미만이면 모든 패널을 위아래로 쌓아요. 순서는 실제 영역, 테스트 영역, Diff, 기록, Virtual DOM이에요.

## 설계 결정

| 결정                                                                                                  | 이유                                                                                                                      | 관련 ADR                     |
| ----------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------- | ---------------------------- |
| 실제 영역은 빨강, 테스트 영역은 파랑, 바뀐 것은 보라로 나눈다                                         | 로고와 같은 뜻이라 어느 쪽인지, 무엇이 바뀌었는지 색만 보고 알아요                                                        | -                            |
| 두 렌더링 결과 박스에는 똑같은 CSS만 건다                                                             | 한쪽에만 걸면 두 영역이 다르게 보여 비교가 흐려져요                                                                       | -                            |
| 페이지는 한 화면에 다 들어가고, 넘치는 내용은 각 칸 안에서 스크롤한다. 두 박스 스크롤은 함께 움직인다 | 내용이 길어져도 패널 위치가 고정되고, 두 영역의 같은 부분을 나란히 볼 수 있어요                                           | -                            |
| 강조 표시는 다음 Patch나 기록 이동 전까지 남긴다                                                      | 잠깐 나타났다 사라지면 무엇이 바뀌었는지 확인할 시간이 부족해요. `fill: 'forwards'`라 속성을 바꾸지 않고도 남길 수 있어요 | [ADR-008](../adr/ADR-008.md) |

## 검증 방법

- 검증 페이지 (실제 브라우저)
  - 두 렌더링 결과 박스의 계산된 스타일(`getComputedStyle`)이 같은지 확인해요.
  - 긴 HTML 코드로 Patch한 뒤 한쪽 박스를 스크롤해 다른 쪽도 같은 위치로 움직이는지 확인해요.
  - 강조 표시 도중에 두 영역을 `toVNode`로 변환해 비교 결과가 같은지 확인해요(FR-W27).
  - Patch하고 몇 초 뒤에도 강조 표시가 남아 있고, 강조된 요소 노드에 `style` 속성이 생기지 않았는지 확인해요. 다음 Patch 뒤에는 이번 변경만, 기록 이동 뒤에는 아무것도 강조되지 않는지 확인해요.
  - 창 높이를 줄여도 페이지 전체 스크롤이 생기지 않는지(`document.documentElement.scrollHeight`가 창 높이와 같은지) 확인해요.
  - 768px 미만으로 줄여 패널이 쌓이는지 확인해요.
