# 스킬 작성

입력: `$ARGUMENTS`

이 스킬이 고치는 파일은 `.claude/skills/<스킬 이름>/SKILL.md`와 `.claude/skills/README.md`예요. 다른 스킬, 규칙, `docs/` 문서는 읽고 보고만 해요.

## 0. 입력 확인

- 첫 단어는 스킬 이름이에요. kebab-case로 써요. (예: `test-case`) 다른 형식이면 kebab-case로 바꾼 이름을 보여 주고 AskUserQuestion으로 확인받아요.
- 둘째 단어부터는 스킬이 할 일 설명이에요. 없으면 대화에서 사용자가 말한 내용을 써요.
- 스킬 이름이 비어 있거나 할 일을 알 수 없으면, AskUserQuestion으로 물어요. 추측해서 진행하지 않아요.
- `.claude/skills/<스킬 이름>/`이 이미 있으면 "고치기"로, 없으면 "새로 만들기"로 진행해요.

## 1. 겹치는 스킬 확인

`.claude/rules/skill-writing.md`의 "시작하기 전" 2~3번을 따라요. 결과는 아래 형식으로 보여 줘요.

| 기존 스킬 | 하는 일 | 겹치는 부분 |
| --------- | ------- | ----------- |

- 겹치는 스킬이 없으면 2단계로 넘어가요.
- 겹치는 스킬이 있으면 멈추고 AskUserQuestion으로 물어요.
  - **기존 스킬 고치기** (추천): 그 스킬 이름으로 "고치기"를 진행해요.
  - **새로 만들기**: 겹치는 부분은 기존 스킬을 가리키고, 겹치지 않는 일만 새 스킬에 써요.
  - **중단**: 아무것도 쓰지 않고 끝내요.

## 2. 읽을 문서

작성 전에 아래를 모두 읽어요.

1. `.claude/rules/skill-writing.md` — 스킬 작성 규칙
2. `.claude/skills/TEMPLATE.md` — 스킬 형식. 4단계는 이 형식을 그대로 따라요.
3. `.claude/skills/README.md` — 스킬 목록, 쓰는 순서, Phase 인자
4. `docs/technical-writing-principles.md` — 문장 기준
5. 1단계에서 찾은 겹치는 스킬, 그리고 "고치기"면 고칠 스킬
6. 새 스킬이 만들 결과물의 템플릿 (예: `docs/design/TEMPLATE.md`, `docs/adr/TEMPLATE.md`)

## 3. 계획 확인

`.claude/rules/skill-writing.md`의 "시작하기 전" 4번대로 호출 방식을 먼저 물어요. "고치기"면 호출 방식을 바꿀 때만 물어요.

그다음 아래 표를 보여 주고 확인을 받아요.

| 항목 | 내용 |
| ---- | ---- |
| 명령어 | 예: `/test-case <phase> [요구사항 ID]` |
| 호출 방식 | 명령어로만 / 명령어 + Claude 자동 호출 / Claude 자동 호출만 |
| 하는 일 | 한 문장 |
| 고치는 파일 | 경로 |
| 읽고 보고만 하는 파일 | 경로 |
| 결과물 형식의 기준 | 템플릿 경로. 없으면 "없음"과 이유 |
| 가리키는 다른 스킬·규칙 | 복사하지 않고 가리킬 절차 (예: Phase 인자 → README "Phase 인자" 절) |
| 새로 작성 / 고치기 | |

사용자가 고치라고 하면 표를 고쳐 다시 보여 줘요.

## 4. 작성

### 형식 지키기

- "새로 만들기"는 `.claude/skills/TEMPLATE.md`를 `.claude/skills/<스킬 이름>/SKILL.md`로 복사해서 시작하고, 템플릿 주석의 작성 규칙대로 칸을 채워요.
- "고치기"는 기존 문서를 템플릿의 단계 순서에 맞추되, 사용자가 요청하지 않은 부분은 바꾸지 않아요.
- 머리 정보의 호출 방식 줄은 3단계에서 고른 값대로 써요.
- 템플릿 주석과 자리표시자는 다 쓴 뒤 모두 지워요.

### 내용 규칙

- `.claude/rules/skill-writing.md`의 "쓸 때" 규칙을 모두 따라요.
- Phase를 받는 스킬은 0절에 README "Phase 인자" 절을 가리키는 한 줄만 써요.
- `.claude/skills/README.md`의 "스킬" 표에 행을 더하거나 고쳐요. 쓰는 순서가 바뀌면 "쓰는 순서" 절도 고쳐요.

## 5. 검증

1. **남은 주석·자리표시자**: `.claude/rules/skill-writing.md`의 "다 쓴 뒤" 1번을 따라요.
2. **참조**: "다 쓴 뒤" 2번을 따라요. 스킬 본문에 적은 경로가 실제로 있는지 `ls`로 확인해요.
3. **README**: 스킬 표의 명령어, 하는 일, 고치는 파일이 SKILL.md와 같아요.

검증 결과는 아래 형식으로 보고해요.

| # | 항목 | 결과 | 문제 위치 | 고칠 내용 |
| - | ---- | ---- | --------- | --------- |

- 이번에 쓴 스킬과 README의 문제는 바로 고치고 다시 검증해요.
- 다른 스킬과 규칙을 고쳐야 하는 문제는 고치지 않고 보고만 해요.
