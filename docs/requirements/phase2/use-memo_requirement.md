## 1. 목표

- 렌더링마다 반복되는 계산의 결과를 hooks 칸에 기억해 두고, deps가 바뀌지 않으면 다시 계산하지 않고 그 값을 돌려준다.
- deps가 "바뀌었는지" 판단하는 의존성 비교 규칙을 정한다. useEffect도 이 규칙을 그대로 쓴다.

## 2. 범위

### 2.1 포함

- useMemo
  - 첫 렌더링에서 계산하고 결과와 deps를 칸에 저장하기
  - deps가 같으면 저장한 값 재사용하기
  - deps가 바뀌면 다시 계산하기
  - 재사용할 때도 `hookIndex` 늘리기
- 의존성 비교
  - 원소마다 `Object.is`로 비교하기
  - deps가 `[]`일 때, 생략했을 때, 길이가 바뀌었을 때의 판단

### 2.2 제외

| 제외 항목                         | 이유                                                                                                                         |
| --------------------------------- | ---------------------------------------------------------------------------------------------------------------------------- |
| useEffect, effect 실행            | [use-effect_requirement.md](use-effect_requirement.md)에서 다룬다. 의존성 비교만 이 문서의 5.2절을 가져다 쓴다.              |
| 렌더링 밖 호출 막기               | 모든 Hook에 같은 규칙이므로 [FR-T01](function-component_requirement.md#53-state-제약)을 따른다.                               |
| 렌더링 중 setState 막기           | useMemo만의 문제가 아니므로 [FunctionComponent 문서](function-component_requirement.md)에서 다룬다. (7절)                     |
| 캐시를 버리고 다시 계산하기       | 실제 React는 메모를 성능 힌트로만 보고 필요하면 버릴 수 있다. 우리는 deps가 같으면 항상 재사용한다. (6.1)                     |
| deps 누락 검사                    | 계산 함수가 무엇을 읽는지 시스템은 알 수 없다. 사용 규칙(2.3)으로 둔다.                                                       |
| useCallback                       | Phase 2 범위가 아니다.                                                                                                        |

### 2.3 사용 규칙 (앱 코드가 지킨다)

> 시스템이 검사할 수 없는 규칙이라 기능 요구사항(5절)에 넣지 않는다. 규칙을 어기면 오류는 나지 않지만 화면에 틀린 값이 나올 수 있다.

- 계산 함수는 순수 함수로 작성한다. 같은 입력이면 같은 결과를 내고, 바깥을 바꾸지 않는다. 계산 함수 안에서 하면 안 되는 일은 다음과 같다.

  | 하면 안 되는 일                          | 이유                                                                                         |
  | ---------------------------------------- | -------------------------------------------------------------------------------------------- |
  | setState                                 | 렌더링 중에 다시 렌더링을 부른다. 값이 계속 바뀌면 무한 루프가 된다.                          |
  | DOM 조작                                 | Patch 전이라 DOM은 이전 상태다. Patch가 덮어쓸 수 있다.                                       |
  | 원본 수정 (`sort`, `reverse`, `splice`)  | state 배열이 바뀌어도 참조는 그대로라 변화를 알아챌 수 없다. `[...todos].sort()`처럼 복사본을 쓴다. |
  | 요청, 타이머, 구독                       | 실행 여부가 메모 상태에 달려 있고 cleanup이 없다. useEffect에서 한다.                          |

- 계산 함수가 읽는 값 중 바뀔 수 있는 값은 모두 deps에 넣는다. (예: `useMemo(() => todos.filter(t => t.text.includes(keyword)), [todos])`는 `keyword`가 빠져 있어, `keyword`가 바뀌어도 이전 검색 결과가 나온다.)
- deps에 넣은 배열 · 객체는 고치지 말고 새로 만들어 state를 바꾼다. 의존성 비교는 참조로 하므로 `todos.push()`처럼 같은 배열을 고치면 다시 계산하지 않는다.

## 3. 용어

> FunctionComponent · useState 용어(hooks 배열, hookIndex, currentComponent, 렌더링 등)는 [function-component_requirement.md 3절](function-component_requirement.md#3-용어)을 따른다.

| 용어                  | 뜻                                                                                                                       |
| --------------------- | ------------------------------------------------------------------------------------------------------------------------ |
| 메모이제이션          | 계산 결과를 저장해 두고, 입력이 같으면 다시 계산하지 않고 저장한 결과를 돌려주는 기법. useMemo는 직전 결과 하나만 저장한다. |
| 계산 함수 (compute)   | useMemo의 첫 번째 인자. 인자 없이 실행해 값을 돌려주는 함수다. (예: `() => todos.filter(t => t.done).length`)              |
| deps (의존성 배열)    | useMemo의 두 번째 인자. 이 배열의 원소가 바뀔 때만 계산 함수를 다시 실행한다. 생략할 수 있다.                               |
| 메모 칸               | useMemo가 쓰는 hooks 칸. 계산 결과(`value`)와 그 결과를 계산할 때의 deps(`deps`)를 함께 저장한다.                          |
| 의존성 비교           | 이전 deps와 이번 deps를 비교해 "바뀌었다" 또는 "같다"로 판단하는 것. useMemo와 useEffect가 함께 쓴다.                      |
| `Object.is`           | 두 값이 같은지 판단하는 JavaScript 함수. `===`와 거의 같지만 `NaN`과 `NaN`은 같다고, `+0`과 `-0`은 다르다고 본다.           |

## 4. 동작 흐름

### 4.1 useMemo 호출

useMemo는 렌더링 중 컴포넌트 함수 안에서, 매 렌더링마다 호출된다. ([FunctionComponent 4.3](function-component_requirement.md#43-렌더링-render))

1. `currentComponent`가 `null`이면 오류를 던진다. ([FR-T01](function-component_requirement.md#53-state-제약))
2. `hookIndex`로 자기 칸 번호(`i`)를 정하고 `hookIndex`를 1 늘린다.
3. 칸(`hooks[i]`)이 있고, 칸의 deps와 이번 deps를 의존성 비교(4.2)한 결과가 "같다"이면 칸의 `value`를 돌려주고 끝낸다. 계산 함수는 실행하지 않는다.
4. 칸이 비어 있거나(첫 렌더링) 의존성 비교 결과가 "바뀌었다"이면 계산 함수를 실행한다.
5. 4단계의 결과와 이번 deps를 칸에 저장한다(`hooks[i] = { kind: 'memo', value, deps }`).
6. 4단계의 결과를 돌려준다.

```text
mount          → App 실행, useMemo → 칸이 비어 있음 → 계산
setText('a')   → App 실행, useMemo → deps [todos] 같음 → 재사용
setTodos([…])  → App 실행, useMemo → deps [todos] 바뀜 → 다시 계산
```

### 4.2 의존성 비교

이전 deps(`prev`)와 이번 deps(`next`)를 받아 다음 순서로 판단한다.

1. 둘 중 하나라도 생략(`undefined`)되었으면 "바뀌었다"로 판단한다.
2. 길이가 다르면 "바뀌었다"로 판단한다.
3. 같은 위치의 원소끼리 `Object.is`로 비교해, 하나라도 다르면 "바뀌었다"로 판단한다.
4. 그 밖에는 "같다"로 판단한다.

deps 배열 자체는 렌더링마다 새로 만들어지므로, 배열끼리가 아니라 원소끼리 비교한다. 그래서 경우별 결과는 다음과 같다.

| 경우                                 | 판단       | useMemo 동작                |
| ------------------------------------ | ---------- | --------------------------- |
| 원소가 모두 `Object.is`로 같음       | 같다       | 재사용                      |
| 원소가 하나라도 다름                 | 바뀌었다   | 다시 계산                   |
| `[]` (이전도 `[]`)                   | 같다       | 첫 렌더링에만 계산          |
| 생략 (`undefined`)                   | 바뀌었다   | 매 렌더링마다 계산          |
| 길이가 바뀜                          | 바뀌었다   | 다시 계산                   |

## 6. 설계로 넘기는 항목

> ([#117](https://github.com/orgs/krafton-jungle-week11-12-team/discussions/117) "8. 요구사항·설계로 넘길 것")

### 6.1 결정된 항목

- deps 길이가 바뀌면 다시 계산한다. (FR-D04)
  - 근거: 판단 원칙은 "애매하면 다시 계산한다"이다. 다시 계산은 느려질 뿐 틀리지 않지만, 잘못된 재사용은 화면에 틀린 값을 낸다. 짧은 쪽까지만 비교하면, deps에 새로 들어온 원소는 비교할 이전 원소가 없어 무시되고 이전 결과를 재사용한다.
  - 실제 React와의 차이: React는 개발 모드에서 경고하고 짧은 쪽까지만 비교한다.
- deps를 생략하면 오류를 던지지 않고 매 렌더링마다 다시 계산한다. (FR-D05)
  - 근거: 이전 deps가 없으면 비교할 기준이 없다. 실제 React와 같은 동작이다.
- deps가 같으면 항상 재사용한다.
  - 실제 React와의 차이: React는 메모를 성능 힌트로만 보고, 필요하면 메모를 버리고 다시 계산할 수 있다.
- 의존성 비교는 이 문서(5.2)에서 정의하고 useEffect가 재사용한다. 두 Hook이 같은 함수를 호출하게 한다.

  ```ts
  function depsChanged(prev?: unknown[], next?: unknown[]): boolean {
    if (!prev || !next) return true; // 생략 → 바뀌었다
    return next.length !== prev.length || next.some((d, i) => !Object.is(d, prev[i]));
  }
  ```

- 메모 칸에는 `{ kind: 'memo', value, deps }`를 저장한다. deps를 저장해 두어야 다음 렌더링에서 바뀌었는지 판단할 수 있다.
- 첫 렌더링은 별도 플래그 없이 칸이 비어 있는지(`undefined`)로 판단한다. useState가 초깃값을 첫 렌더링에만 쓰는 방식과 같다.

- hooks 칸의 타입: 모든 칸을 `kind`로 구분하는 유니언으로 둔다. 메모 칸은 `{ kind: 'memo', value, deps }`다. 타입 정의와 근거는 [FunctionComponent 6.1](function-component_requirement.md#61-결정된-항목)에 둔다.
- `depsChanged`는 `src/deps.ts`에 둔다. ([의존성 비교 설계](../../design/phase2/deps.md))
  - 근거: useMemo와 useEffect가 같은 함수를 import한다. 한쪽 Hook 파일에 두면 다른 Hook이 그 파일에 기대게 된다.

## 7. 추후 논의

- 렌더링 중 setState 막기: 계산 함수 안에서 setState를 부르면 렌더링 중에 다시 렌더링을 부른다. 렌더링 중 플래그를 두고 막을지 FunctionComponent · useState 문서의 설계에서 정한다.
- useState 지연 초기화: 이번 단계에서는 FR-S에 넣지 않기로 했다(2026-11-11). `useState(loadFromStorage())`는 매 렌더링마다 `loadFromStorage()`를 실행하고 결과를 버린다. 실제 React처럼 `useState(() => loadFromStorage())`를 첫 렌더링에만 실행하는 기능은 [최종 웹 페이지 요구사항의 2차 추가 기능(FR-AX04)](../app_requirement.md#59-2차-추가-기능)으로 미뤘다.
- deps 길이가 바뀌었을 때 개발용 경고를 낼지: 길이 변경은 대부분 계산 함수가 읽는 값을 deps에서 빠뜨린 실수에서 나온다.
