# 최종 검증

입력: `$ARGUMENTS`

이 스킬은 읽고 보고만 해요. `src/` 코드와 요구사항, 설계, ADR 문서를 고치지 않아요. 모든 구현이 끝났을 때만 실행하고, `/implement-design`이 끝나면 마지막에 자동으로 실행돼요. 워크플로우는 `.claude/skills/README.md`의 "쓰는 순서" 절을 봐요.

## 0. 입력 확인

- 첫 단어는 Phase예요. `.claude/skills/README.md`의 "Phase 인자" 절대로 읽어요.

## 1. 구현 완료 확인

최종 검증은 모든 구현이 끝났을 때만 해요. 아래를 확인해요.

1. **테스트 통과**: `npm test` 전체가 통과해요.
2. **테스트 존재**: 이 Phase 요구사항 문서에서 비고가 "삭제됨"이 아닌 요구사항 ID가 모두 `src/**/*.test.ts` 주석에 있어요. 단위 테스트로 확인할 수 없는 요구사항은 6번(검증 페이지)에서 확인하니 빼도 돼요.

결과는 아래 형식으로 보여 줘요.

| 항목 | 결과 (통과 / 실패) | 내용 |
| ---- | ------------------ | ---- |

- 하나라도 실패면 최종 검증을 하지 않고 멈춰요. 테스트가 없으면 `/make-testcase`를, 테스트가 실패하면 `/implement-tc`를 먼저 돌리라고 안내해요.

## 2. 읽을 문서

검증 전에 아래를 모두 읽어요.

1. `docs/requirements/<phase>/` 아래 요구사항 문서 전부
2. 이 Phase의 설계 문서 전부와, 이어받는 앞 Phase 설계 문서 (위치는 README "Phase 인자" 절)
3. `docs/adr/` — 이 Phase 요구사항이나 설계 문서가 가리키는 ADR
4. `src/` 코드와 테스트 파일
5. `.claude/skills/doc-check/SKILL.md` — 4단계 5번에서 이 절차를 따라요.

## 3. 검증 범위

이 Phase 전체를 대상으로 해요. 앞 Phase 테스트도 함께 돌려요. 따로 확인받지 않고 4단계로 넘어가요.

## 4. 검증

항목마다 문제가 없어도 결과 표에 한 줄을 남겨요.

1. **테스트·타입 검사·빌드**: `npm test`, `npm run typecheck`, `npm run build`가 모두 통과해요.
2. **요구사항 추적**: 요구사항 ID마다 그 요구사항을 확인하는 테스트와, 그 동작을 하는 구현 위치를 찾아요. 결과는 아래 표로 보여 줘요.

   | 요구사항 ID | 요약 | 테스트 (파일:케이스) | 구현 위치 (파일:함수) | 결과 |
   | ----------- | ---- | -------------------- | --------------------- | ---- |

3. **설계 일치**: 설계 문서 "자료구조"의 타입과 "인터페이스"의 함수 시그니처가 `src/`의 export와 같아요. 설계 결정과 경계 케이스대로 동작하는지도 코드에서 확인해요.
4. **ADR 반영**: 승인된 ADR의 결정이 구현에 반영됐고, 기각된 ADR의 선택지를 따르지 않았어요.
5. **문서 정합성**: `doc-check` 절차를 `<phase>` 입력으로 따라요. 문서끼리 맞지 않으면 구현이 어느 쪽을 따랐는지 함께 적어요.
6. **검증 페이지**: 단위 테스트로 확인할 수 없는 요구사항(화면 동작, 강조 표시 등)을 목록으로 만들고, `npm run dev`로 개발 서버를 띄워 브라우저에서 확인해요. 브라우저로 확인할 수 없으면 목록을 사용자에게 넘겨 확인을 부탁하고, 결과는 "확인 불가"로 적어요.
7. **범위**: 요구사항 2.2 "제외"에 있는 기능이 구현되지 않았어요.

## 5. 마지막 보고

검증 결과는 아래 형식으로 보고해요. 문제 위치는 `파일:줄` 링크로 적어요.

| # | 항목 | 결과 (통과 / 문제 / 확인 불가) | 문제 위치 | 고칠 내용 | 고칠 곳 (구현 / 테스트 / 요구사항 / 설계 / ADR) |
| - | ---- | ------------------------------ | --------- | --------- | ----------------------------------------------- |

표 아래에 아래를 적어요.

- **최종 판정**: "통과" 또는 "문제 있음". 문제가 하나라도 있으면 "문제 있음"이에요.
- 요구사항 추적 표 (4단계 2번)
- 문제마다 다음에 쓸 스킬: 구현은 `/implement-design`, 테스트는 `/make-testcase`, 문서는 `/design-doc`이나 `/doc-check`
- 사용자가 직접 확인해야 할 검증 페이지 항목
- 문서 검수: 이 스킬은 문서를 쓰지 않아요. "검수할 문서 없음"이라고 적어요. (4단계 5번의 문서 정합성 결과는 따로 적어요.)
