# ADR-005: 입력 유효성 검사를 두지 않는다

- 상태: 승인됨
- 관리 범위: mini-react 저장소 (docs/adr)

## 개요

사용자가 입력한 HTML 코드를 검사할지에 대한 결정이에요. 이 글을 읽으면 왜 FR-W09(변환할 수 없는 HTML 오류 처리)를 없앴는지 알 수 있어요.

## 맥락

FR-W09를 지키려면 "변환할 수 없는 HTML"의 기준이 필요했어요. 그런데 브라우저 HTML 파서는 어떤 문자열이든 오류 없이 DOM을 만들고, 닫히지 않은 태그나 잘못된 중첩은 정해진 규칙으로 보정해요. 파싱 오류도 API로 알려 주지 않아요.

## 고려한 선택지

검토한 대안과 장단점은 다음과 같아요.

### 선택지 A: 엔진이 표현할 수 없는 입력을 기준으로 정의

- 장점: 이상한 입력을 사용자에게 알려 줄 수 있어요.
- 단점: 빈 입력, 텍스트만 있는 입력, 루트 여러 개 등 경우마다 따져야 해요.

### 선택지 B: 엄격한 검사 (XHTML 파싱, 입력과 파싱 결과 비교)

- 장점: 닫히지 않은 태그 같은 실수를 잡아요.
- 단점: 보정과 오류를 구별하지 못해 정상 HTML도 오류로 잡아요.

### 선택지 C: 검사하지 않음

- 장점: 예외 분기와 오류 UI가 필요 없어요.
- 단점: 입력과 렌더링 결과가 다를 수 있어요.

## 결정

HTML 코드의 유효성 검사를 하지 않는다. 브라우저가 파싱한 DOM은 빈 문자열을 포함해 모두 Virtual DOM 트리로 변환한다. FR-W09는 삭제한다.

## 근거

ADR-004에 따라 두 영역 모두 파싱한 DOM을 쓰므로, 엔진이 받는 입력은 항상 정상 DOM이에요. 보정도 두 영역에 똑같이 적용돼요. 변환은 영역 컨테이너의 자식부터 시작하므로 텍스트만 있거나 루트가 여러 개인 입력도 그대로 처리돼요.

## 예상되는 결과

이 결정으로 예상되는 영향은 다음과 같아요.

- 긍정적 영향: Patch 흐름에 예외 처리가 없어 구현과 테스트가 단순해져요.
- 부정적 영향 / 리스크: 보정이 크게 일어나면 사용자가 헷갈릴 수 있어요. 테스트 기댓값은 보정된 결과로 써야 해요.

## 관련 참조 문서

- React요구사항(오동환) 범위: 제외 항목(HTML 에디터 구현)
- React요구사항(오동환) FR-E01: DOM을 Virtual DOM 트리로 변환
- React요구사항(오동환) FR-E05: Patch 시 Diff로 이전/새 Virtual DOM 비교
- FR-W09(변환할 수 없는 HTML 오류 처리): 이 결정으로 삭제됨
- ADR-004(오동환): 테스트 영역 렌더링 결과는 HTML을 파싱한 DOM으로 만든다
