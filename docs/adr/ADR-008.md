# ADR-008: Diff 결과 표시는 Diff와 분리하고, 화면 표시는 브라우저에 물어 판단한다

- 상태: 승인됨
- 관리 범위: mini-react 저장소 (docs/adr)

## 개요

Patch 후 바뀐 부분을 어떻게 보여줄지에 대한 결정이에요. 이 글을 읽으면 공백·주석처럼 화면에 안 보이는 변경을 하이라이트와 요약 문구에서 각각 어떻게 다루는지, 왜 `innerText`로 보이는지 판단하는지 알 수 있어요.

## 맥락

ADR-007에 따라 Diff는 공백·주석 변경도 잡고, 이런 변경만 있어도 Patch 버튼이 켜져요. 하지만 이런 변경은 화면에 안 보일 때가 많아 하이라이트할 자리가 없어요. 그러면 사용자가 Patch를 눌러도 아무 반응이 없는 것처럼 보여요. 공백이 보이는지는 태그 종류, 위치, CSS `white-space`에 따라 달라요.

## 고려한 선택지

### 선택지 A: 공백 규칙을 직접 구현해 거른다

- 장점: 외부 API에 의존하지 않아요.
- 단점: 블록 사이, 줄 앞뒤, 이웃 노드 합치기, `pre`·`&nbsp;` 예외를 모두 맞춰야 해요.

### 선택지 B: `innerText`로 브라우저에 묻는다

- 장점: 브라우저가 공백 규칙을 그대로 적용해 줘요.
- 단점: 읽을 때 Reflow가 일어나요.

## 결정

변경 표시는 Diff와 분리하고, 텍스트 변경이 보이는지는 `innerText`로 판단한다. Patch 후에는 하이라이트와 함께 변경 개수 요약을 보여 준다.

| Diff 결과               | 화면 하이라이트                      | 요약 문구에서 세는 곳                         |
| ----------------------- | ------------------------------------ | --------------------------------------------- |
| 요소·속성 변경          | 표시                                 | 변경                                          |
| 텍스트 변경 (공백 포함) | 부모 `innerText`가 바뀌었을 때만     | 변경. 하이라이트하지 않았으면 안 보이는 변경  |
| 주석 변경               | 표시 안 함                           | 변경, 안 보이는 변경                          |

1. 요약 문구는 "변경 N개 (화면에 안 보이는 변경 M개)"로 보여 준다. N은 Diff 결과의 변경 개수, M은 주석 변경과 부모 `innerText`가 바뀌지 않은 텍스트 변경의 개수다. M이 0이면 괄호 부분을 뺀다.
2. 부모 `innerText`는 Patch 전 값과 Patch 후 값을 비교한다. 그래서 Patch 전 값을 미리 읽어 둔다.
3. 하이라이트는 `element.animate()`로 한다. 실제 영역 DOM에 속성을 붙이지 않는다.
4. 변경마다 항목을 보여 주는 변경 로그(공백은 `·`, 줄바꿈은 `↵`로 표시)는 2차 기능으로 미룬다.

## 근거

브라우저 규칙을 다시 만드는 것보다 브라우저에 묻는 게 정확해요. Reflow는 Patch 때 한 번이라 감수해요.

요약 문구는 하이라이트 판단에서 나온 결과를 세기만 하면 돼서 비용이 거의 없어요. 변경 로그는 항목 타입과 노드 위치 표시까지 설계해야 해서 Phase 1 일정에 넣지 않아요.

## 예상되는 결과

- 긍정적 영향: 화면에 안 보이는 변경만 있는 Patch도 요약 문구로 반응을 확인할 수 있어요.
- 부정적 영향 / 리스크: 화면에 렌더링되지 않은 요소(`display: none`)는 `innerText`로 판단할 수 없어요. 변경 로그가 없어서 안 보이는 변경이 무엇인지까지는 알 수 없어요.
