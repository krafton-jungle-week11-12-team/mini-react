# 스킬 작성 규칙

스킬을 새로 만들거나 고칠 때 따라요. 스킬도 문서라서 문장은 [문서 작성 규칙](docs-writing.md)을 함께 따라요.

## 시작하기 전

1. **템플릿에서 시작해요.** 새 스킬은 [스킬 템플릿](../skills/TEMPLATE.md)을 `.claude/skills/<스킬 이름>/SKILL.md`로 복사해서 쓰고, 템플릿 주석의 작성 규칙을 따라요. 기존 스킬을 고칠 때도 템플릿의 단계 순서(확인 → 읽기 → 계획 확인 → 작성 → 검증 → 보고)에 맞춰요.
2. **겹치는 스킬이 있는지 봐요.** [스킬 목록](../skills/README.md)과 `.claude/skills/` 아래 스킬을 먼저 읽어요. 하려는 일이 이미 있으면 새로 만들지 않고 그 스킬을 고쳐요.
3. **범위를 정해요.** 스킬 하나는 일 하나만 해요. (예: 설계 문서 작성, 문서 검증, 테스트 케이스 작성) 범위가 애매하면 쓰기 전에 AskUserQuestion으로 물어요.
4. **호출 방식을 물어요.** 스킬을 새로 만들 때는 항상 AskUserQuestion으로 명령어로 만들지 물어요. 사용자가 요청에서 이미 정했으면 묻지 않아요. 고르는 값에 따라 머리 정보를 어떻게 쓰는지는 [스킬 템플릿](../skills/TEMPLATE.md) 주석에 있어요.
   - **명령어로만** (추천): 사용자가 `/<스킬 이름>`으로 불러야만 실행돼요. 파일을 쓰거나 고치는 스킬에 맞아요.
   - **명령어 + Claude 자동 호출**: 사용자도 부를 수 있고, 요청이 description과 맞으면 Claude도 알아서 불러요.
   - **Claude 자동 호출만**: 명령어 목록에 나오지 않고 Claude만 불러요. 배경 지식을 주는 스킬에 맞아요.

## 쓸 때

- **description**: 무엇을 하는지와 파일을 고치는지를 한 문장에 함께 써요. (예: "~를 검증하고 결과만 보고한다. 문서는 고치지 않는다.")
- **고치는 범위**: 스킬이 고치는 파일과 읽고 보고만 하는 파일을 본문 앞쪽에 나눠 적어요. 범위 밖 파일의 문제는 고치지 않고 보고만 해요.
- **한 곳에만 쓰기**: 다른 스킬이나 규칙에 이미 있는 절차는 복사하지 않고 "`<경로>`의 N단계를 따라요"처럼 가리켜요. 복사하면 한쪽만 고쳐져 어긋나요.
- **경로**: 저장소 루트 기준 경로로 쓰고, 적은 경로가 실제로 있는지 `ls`로 확인해요.
- **기준이 되는 파일**: 결과물 형식은 `docs/` 아래 템플릿(`docs/design/TEMPLATE.md`, `docs/adr/TEMPLATE.md` 등)을 가리켜요. 스킬 안에 형식을 새로 정의하지 않아요.
- **결과 보고**: 확인·검증 결과는 표로 보여 주고, 문제 위치는 `파일:줄`로 적어요.
- **doc-check 검수**: 모든 스킬은 결과를 주기 전에 이번에 쓰거나 고친 문서를 `doc-check`로 검수해요. `doc-check`는 사용자만 부를 수 있는 스킬이라, 스킬 본문에는 "`.claude/skills/doc-check/SKILL.md`를 읽고 그 절차대로 검수해요"라고 써요. 이번에 쓴 문서의 문제는 고치고 다시 검수해요. `doc-check` 자신은 빼요.

## 다 쓴 뒤

1. 남은 템플릿 주석(`<!--`)과 자리표시자(`[스킬 이름]`, `[항목]` 등)를 `grep`으로 찾아 지워요.
2. 스킬을 고쳤다면 그 스킬을 가리키는 다른 스킬과 규칙의 경로·단계 번호가 맞는지 `grep`으로 확인해요.
3. 새 세션에서 `/<스킬 이름>`을 한 번 실행해 봐요. 스킬 목록은 세션을 열 때 읽어서, 지금 세션에서는 새 스킬이 안 보일 수 있어요.
