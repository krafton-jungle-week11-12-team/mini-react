## 개요

State History는 기록의 상태(`{ html, vdom }`)를 순서대로 쌓고 현재 위치를 관리해요. 이 문서를 읽으면 기록을 저장하고 이동하는 규칙을 알고 State History를 구현할 수 있어요.

## 다루는 요구사항

| ID       | 요구사항 요약                                                              | 이 문서에서 다루는 곳 |
| -------- | -------------------------------------------------------------------------- | --------------------- |
| FR-W07   | 페이지가 로드되면 `{ html, vdom }`을 `history[0]`으로 저장해요             | 동작 방식             |
| FR-W17   | Patch하면 새 기록을 현재 위치 바로 뒤에 저장해요                           | 동작 방식             |
| FR-W18   | 뒤로가기로 이동한 위치에서 Patch하면 현재 위치 뒤의 기록을 모두 지워요     | 동작 방식             |
| FR-W18-2 | 앞으로가기로 이동한 위치에서 Patch하면 현재 위치 뒤의 기록을 모두 지워요   | 동작 방식             |
| FR-W21   | 현재 위치가 첫 기록이면 뒤로가기 버튼을 비활성화해요                       | 인터페이스            |
| FR-W29   | 현재 위치가 마지막 기록이면 앞으로가기 버튼을 비활성화해요                 | 인터페이스            |

## 위치와 흐름

```text
검증 페이지 ──(로드, Patch, 기록 이동)──▶ State History ──▶ 현재 기록, 버튼 상태
```

- 입력을 주는 곳: [검증 페이지](page.md)(로드 때 첫 기록, Patch 때 새 기록, 뒤로가기·앞으로가기 때 위치 이동)
- 출력을 받는 곳: [Diff](diff.md)(이전 트리로 현재 기록의 `vdom`. FR-W13), 검증 페이지(이동한 기록으로 두 영역 복원, 버튼 활성화 상태)

## 설계 결정

| 결정                                                                         | 이유                                                                     | 관련 ADR                     |
| ---------------------------------------------------------------------------- | ------------------------------------------------------------------------ | ---------------------------- |
| 기록 하나는 `{ html 원문, vdom }`으로 저장한다. DOM과 Diff 결과는 저장하지 않는다 | DOM과 Diff 결과는 다시 만들 수 있는 파생값이에요                     | [ADR-006](../adr/ADR-006.md) |
| 페이지 로드 시점을 첫 기록으로 저장한다                                      | 첫 Patch의 이전 트리가 필요해요                                          | [ADR-006](../adr/ADR-006.md) |
| 마지막 기록이 아닌 위치에서 Patch하면 뒤의 기록을 모두 지우고 새 기록을 저장한다 | 새 기록 바로 앞이 Patch 전 상태여야 Diff가 맞아요                    | [ADR-006](../adr/ADR-006.md) |
| HTML 코드는 원문 그대로 저장한다                                             | 기록을 이동할 때 사용자가 입력한 공백까지 되돌려요                       | [ADR-006](../adr/ADR-006.md) |

## 경계 케이스

| 경우                                   | 입력 예시                                       | 기대 동작                                                           | 관련 요구사항   |
| -------------------------------------- | ----------------------------------------------- | ------------------------------------------------------------------- | --------------- |
| 로드 직후                              | 기록 1개, 위치 0                                | 뒤로가기와 앞으로가기 모두 비활성화돼요                             | FR-W21, W29     |
| 뒤로 간 위치에서 Patch                 | 기록 3개에서 두 번 뒤로 간 뒤 Patch             | 뒤의 기록이 지워지고 새 기록이 들어가 총 2개, 앞으로가기 비활성화   | FR-W18          |
| 앞으로 간 위치에서 Patch               | 기록 4개에서 세 번 뒤로, 한 번 앞으로 간 뒤 Patch | 위치 2, 3이 지워지고 새 기록이 들어가 총 3개, 앞으로가기 비활성화 | FR-W18-2        |
| 첫 기록에서 뒤로가기를 직접 호출       | 위치 0에서 뒤로가기 함수 호출                   | [정하기]                                                            | FR-W21          |
| 마지막 기록에서 앞으로가기를 직접 호출 | 마지막 위치에서 앞으로가기 함수 호출            | [정하기]                                                            | FR-W29          |

## 검증 방법

- 단위 테스트: 위 경계 케이스마다 기록 개수, 현재 위치, 버튼 활성화 상태를 확인해요. 새 기록의 `html`이 Patch한 HTML 코드와 같은지도 확인해요(FR-W17).
- 검증 페이지: 로드 직후, Patch 직후, 뒤로 간 뒤에 뒤로가기·앞으로가기 버튼의 활성화 상태를 확인해요(FR-W21, W29).

## 정하지 않은 것

- State History 기록 개수 상한: 요구사항 6절.
- 범위를 벗어난 이동을 직접 호출했을 때의 동작: 버튼은 비활성화되지만 함수가 직접 호출될 수 있어요.
