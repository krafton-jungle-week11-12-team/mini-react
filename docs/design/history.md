# State History 설계

- 상태: 리뷰 중
- 작성자: 임동호
- 관련 이슈: #12

## 개요

State History는 기록의 상태(`{ html, vdom }`)를 순서대로 쌓고 현재 위치를 관리해요. 이 문서를 읽으면 기록을 저장하고 이동하는 규칙을 알고, 다른 모듈과 상관없이 State History를 구현하거나 바꿔 끼울 수 있어요.

## 다루는 요구사항

| FR-W18   | 뒤로가기로 이동한 위치에서 Patch하면 현재 위치 뒤의 기록을 모두 지워요   | 동작 방식, 경계 케이스, 검증 방법                      |

| FR-W19   | 뒤로가기하면 직전 기록으로 이동해요                                      | 인터페이스(위치 옮기기), 검증 방법                     |
| FR-W20   | 앞으로가기하면 다음 기록으로 이동해요                                    | 인터페이스(위치 옮기기), 검증 방법                     |
| FR-W21   | 현재 위치가 첫 기록이면 뒤로가기 버튼을 비활성화해요                     | 인터페이스(이동 가능 여부 알려 주기), 경계 케이스      |
| FR-W29   | 현재 위치가 마지막 기록이면 앞으로가기 버튼을 비활성화해요               | 인터페이스(이동 가능 여부 알려 주기), 경계 케이스      |

State History는 기록을 저장하고 위치를 옮기며, 이동할 수 있는지 알려 줘요. 아래 일은 [검증 페이지 설계](page.md)에서 다뤄요.

- 두 영역을 기록의 상태로 바꾸는 일(FR-W19, FR-W20)
- 버튼을 활성화하거나 비활성화하는 일(FR-W21, FR-W29)
- 로드와 Patch 때 기록을 만들어 넘기는 일(FR-W07, FR-W17)

## 위치와 흐름

```text
검증 페이지 ──(첫 기록, 새 기록, 위치 이동)──▶ State History ──▶ 현재 위치 기록, 이동 가능 여부 ──▶ 검증 페이지
```

- 입력을 주는 곳: [검증 페이지](page.md)
  - 로드 때 첫 기록을 넘겨 State History를 만들어요.
  - Patch 때 새 기록을 넘겨요. 바뀐 내용이 없으면 넘기지 않아요(FR-W28).
  - 뒤로가기·앞으로가기 버튼을 누르면 위치를 옮겨요.
- 출력을 받는 곳: 검증 페이지
  - 현재 위치 기록의 `vdom`을 꺼내 [Diff](diff.md)의 이전 트리로 넘겨요(FR-W13).
  - 이동한 기록으로 두 영역을 복원하고, 이동 가능 여부로 버튼을 활성화하거나 비활성화해요.
- State History는 다른 모듈을 호출하지 않아요. 기록의 내용도 읽지 않아요.

## 자료구조

```ts
type StateHistory<T> = {
  current(): T;
  push(entry: T): void;
  back(): T | null;
  forward(): T | null;
  canBack(): boolean;
  canForward(): boolean;
  readonly index: number;
  readonly length: number;
};

type HistoryEntry = {
  html: string;
  vdom: VNode[];
};
```

`VNode`는 [Virtual DOM 변환 설계](vdom.md)의 타입이에요. `StateHistory`의 메서드는 아래 인터페이스에서 설명해요.

- `StateHistory<T>` — 기록 목록과 현재 위치. `T`는 기록 하나의 타입이에요. State History는 `T`의 내용을 읽지 않아요. 검증 페이지는 `StateHistory<HistoryEntry>`로 써요.
  - `index: number` — 현재 위치. 0 이상 `length - 1` 이하예요. (예: 로드 직후 `0`)
  - `length: number` — 저장된 기록 개수. 1 이상이에요. (예: Patch를 두 번 한 뒤 `3`)
- `HistoryEntry` — 검증 페이지가 저장하는 기록 하나([ADR-006](../adr/ADR-006.md)).
  - `html: string` — 그 시점의 HTML 코드 원문. 사용자가 입력한 공백과 줄바꿈까지 그대로 담아요. (예: 샘플 HTML 코드)
  - `vdom: VNode[]` — 그 HTML 코드로 만든 DOM을 변환한 Virtual DOM 트리의 루트 목록. (예: `toVNode(실제 영역 컨테이너)`의 결과)

## 인터페이스

```ts
function createHistory<T>(first: T): StateHistory<T>;
```

- `first: T` — 첫 기록. 검증 페이지는 로드 때 만든 `{ html: 샘플 HTML 코드, vdom }`을 넣어요(FR-W07). (예: `{ html: SAMPLE_HTML, vdom: toVNode(realRoot) }`)
- 반환값: 기록 1개, 현재 위치 0인 State History.
- 부수 효과: 없음.

`StateHistory`의 메서드는 아래와 같아요.

| 메서드         | 하는 일                                                                                                  | 반환값                                                 |
| -------------- | -------------------------------------------------------------------------------------------------------- | ------------------------------------------------------ |
| `current()`    | 현재 위치 기록을 돌려줘요                                                                                | `T`                                                    |
| `push(entry)`  | 현재 위치 뒤의 기록을 모두 지우고 `entry`를 끝에 붙여요. 그 뒤 현재 위치를 새 기록으로 옮겨요            | 없음                                                   |
| `back()`       | 현재 위치를 직전 기록으로 옮겨요(`index - 1`)                                                            | 이동한 기록. 첫 기록이면 위치를 바꾸지 않고 `null`     |
| `forward()`    | 현재 위치를 다음 기록으로 옮겨요(`index + 1`)                                                            | 이동한 기록. 마지막 기록이면 위치를 바꾸지 않고 `null` |
| `canBack()`    | `back()`으로 이동할 수 있는지 알려 줘요. 검증 페이지는 `false`면 뒤로가기 버튼을 비활성화해요(FR-W21)    | `index > 0`                                            |
| `canForward()` | `forward()`로 이동할 수 있는지 알려 줘요. 검증 페이지는 `false`면 앞으로가기 버튼을 비활성화해요(FR-W29) | `index < length - 1`                                   |

이 인터페이스만 지키면 내부 저장 방식(배열, 연결 리스트 등)은 바꿔도 돼요. 검증 페이지는 `createHistory`를 직접 import하지 않고 넘겨받아 써요([검증 페이지 설계](page.md#인터페이스)).

## 동작 방식

### 저장 (`push`)

1. 현재 위치 뒤에 기록이 있으면 모두 지워요. 뒤로가기로 왔든 앞으로가기로 왔든 같아요(FR-W18, FR-W18-2).
2. 새 기록을 목록 끝에 붙여요(FR-W17).
3. 현재 위치를 새 기록으로 옮겨요.

### 이동 (`back`, `forward`)

1. 옮길 위치가 0 이상 `length - 1` 이하인지 확인해요. 범위 밖이면 위치를 바꾸지 않고 `null`을 돌려줘요.
2. 현재 위치를 옮기고 그 기록을 돌려줘요(FR-W19, FR-W20).

예시 (FR-W18-2의 확인 방법):

```text
기록 [h0, h1, h2, h3], 위치 3
back() → 위치 2, back() → 위치 1, back() → 위치 0, forward() → 위치 1
push(h4)
  1. 위치 1 뒤의 h2, h3을 지워요 → [h0, h1]
  2. h4를 붙여요                 → [h0, h1, h4]
  3. 위치를 2로 옮겨요           → canForward() === false
```

## 설계 결정

| 결정                                                                                      | 이유                                                                                                                                    | 관련 ADR                     |
| ----------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------- |
| 기록 하나는 `{ html 원문, vdom }`으로 저장한다. DOM과 Diff 결과는 저장하지 않는다         | DOM과 Diff 결과는 다시 만들 수 있는 파생값이에요                                                                                        | [ADR-006](../adr/ADR-006.md) |
| 페이지 로드 시점을 첫 기록으로 저장한다                                                   | 첫 Patch의 이전 트리가 필요해요                                                                                                         | [ADR-006](../adr/ADR-006.md) |
| 마지막 기록이 아닌 위치에서 저장하면 현재 위치 뒤의 기록을 모두 지우고 새 기록을 저장한다 | 새 기록 바로 앞이 Patch 전 상태여야 Diff가 맞아요                                                                                       | [ADR-006](../adr/ADR-006.md) |
| HTML 코드는 원문 그대로 저장한다                                                          | 기록을 이동할 때 사용자가 입력한 공백까지 되돌려요                                                                                      | [ADR-006](../adr/ADR-006.md) |
| State History는 기록 타입을 `T`로 받고 내용을 읽지 않는다                                 | Virtual DOM 트리의 모양이나 기록에 넣는 값이 바뀌어도 State History는 고치지 않아도 돼요                                                | -                            |
| 범위 밖으로 이동하면 위치를 바꾸지 않고 `null`을 돌려준다                                 | 버튼이 비활성화돼 있어도 메서드는 직접 호출될 수 있어요. `null`을 받은 쪽은 아무것도 하지 않아요                                        | -                            |
| 저장할 때 기록을 복사하지 않는다                                                          | `toVNode`가 매번 새 객체를 만들고, Phase 1에는 저장된 기록을 고치는 모듈이 없어요. Phase 2에서 VNode를 고치는 코드가 생기면 다시 정해요 | -                            |
| 기록 개수에 상한을 두지 않는다                                                            | 학습용 페이지라 기록이 많이 쌓이지 않아요. 기록 하나는 HTML 코드와 트리 하나라 가벼워요(요구사항 6절)                                   | -                            |

## 검증 방법

- 단위 테스트: 위 경계 케이스마다 `length`, `index`, `canBack()`, `canForward()`를 확인해요. 기록은 `{ html, vdom }`이 아니라 문자열(`'h0'`, `'h1'`)이나 빈 객체로 넣어도 돼요. State History는 내용을 읽지 않아요.
  - FR-W07: `createHistory(h0).current()`가 `h0`인지 확인해요.
  - FR-W17: `push(h1)` 뒤 `current()`가 `h1`인지 확인해요.
  - FR-W18, W18-2: 저장한 뒤 `back()`을 끝까지 호출해, 돌려받은 기록이 남아야 할 기록(`h0`, `h1` 등)과 같은 객체(`===`)인지 확인해요.
  - FR-W19, W20: `[h0, h1, h2]`에서 `back()`이 `h1`을, 이어서 `forward()`가 `h2`를 같은 객체(`===`)로 돌려주는지 확인해요. 이동 뒤 `current()`도 같은 기록인지 확인해요.
- 검증 페이지: 로드 직후, Patch 직후, 뒤로 이동한 뒤에 뒤로가기·앞으로가기 버튼의 활성화 상태를 확인해요(FR-W21, W29).
