# ADR-006: State History 기록은 { html 원문, vdom }으로 저장한다

- 상태: 승인됨
- 관리 범위: mini-react 저장소 (docs/adr)

## 개요

State History 기록 하나에 무엇을 저장할지에 대한 결정이에요. 이 글을 읽으면 왜 HTML 원문과 Virtual DOM 트리만 저장하는지, 어떤 규칙을 지켜야 하는지 알 수 있어요.

## 맥락

기록은 두 곳에 쓰여요. Patch는 현재 기록의 Virtual DOM 트리와 새 트리를 Diff로 비교하고, 기록 이동은 사용자가 쓴 HTML 원문을 공백까지 되돌려야 해요.

## 고려한 선택지

검토한 대안과 장단점은 다음과 같아요.

### 선택지 A: DOM까지 모두 저장

- 장점: 이동할 때 저장한 DOM을 그대로 붙이면 돼요.
- 단점: DOM은 Patch로 계속 바뀌고, 복제하면 무거워요.

### 선택지 B: Virtual DOM 트리만 저장

- 장점: 가장 가벼워요.
- 단점: 다시 만든 HTML은 공백과 주석이 빠져 원문을 되돌릴 수 없어요.

### 선택지 C: { html 원문, vdom }

- 장점: 원문을 되돌리고, Virtual DOM 트리는 바로 Diff에 써요.
- 단점: vdom은 html에서 다시 만들 수 있어 정보가 중복돼요.

## 결정

기록 하나는 { html 원문, vdom }으로 저장한다. DOM, 렌더링 결과, Diff 결과는 저장하지 않는다. Patch 전 Virtual DOM 트리는 직전 기록의 vdom을 쓴다. 이를 위해 다음 규칙을 지킨다.

1. 페이지 로드 시점을 첫 기록으로 저장한다.
2. 마지막 기록이 아닌 위치에서 Patch하면, 현재 위치 뒤의 기록을 모두 지우고 새 기록을 저장한다.
3. 규칙 2는 뒤로가기와 앞으로가기 모두에 적용한다.

## 근거

DOM과 렌더링 결과는 다시 만들 수 있는 파생값이에요. Diff 결과도 앞뒤 기록으로 다시 계산할 수 있어요. 한 기록의 "Patch 후"가 다음 기록의 "Patch 전"이므로 Patch 전 트리를 따로 저장할 필요가 없어요. 다만 규칙 2, 3이 없으면 새 기록 바로 앞이 Patch 전 상태가 아니게 되어 Diff가 틀려져요.

## 예상되는 결과

이 결정으로 예상되는 영향은 다음과 같아요.

- 긍정적 영향: 기록 이동 때 원문이 그대로 돌아오고, 저장 구조가 단순해요.
- 부정적 영향 / 리스크: 지운 기록은 되돌릴 수 없어요. 기록이 많아지면 상한(6절)을 정할 때 Diff 캐시도 함께 검토해요.
