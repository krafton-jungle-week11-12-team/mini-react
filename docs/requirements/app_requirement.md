## 1. 목표

- Phase 2에서 만든 mini-react(h, FunctionComponent, useState, useMemo, useEffect)로 할 일 앱을 만들어, 사용자의 입력과 클릭에 따라 화면이 바뀌는 것을 보여 준다.
- 앱 하나로 useState, useMemo, useEffect, key Diff, 이벤트 props, 제어 입력을 모두 쓴다. 발표에서 기능 하나를 쓸 때마다 개념 하나를 설명할 수 있게 한다.
- 루트 컴포넌트 하나가 state를 모두 갖고, 자식 컴포넌트는 props만 받아 그리는 구조로 만든다. ([앱 작성 규칙 FR-A01~A12](phase2/function-component_requirement.md#54-앱-작성-규칙))

## 2. 범위

### 2.1 포함

- 페이지 구성
  - 첫 화면(`index.html`)에서 Phase 1 검증 페이지와 할 일 앱으로 가는 링크
  - 할 일 앱 페이지(`phase2.html`)
- 할 일 앱 (1차)
  - 추가 (추가 버튼, Enter 키)
  - 끝냄 표시 (체크박스)
  - 삭제
  - 필터 (전체, 남은 일, 끝낸 일)
  - 끝낸 일 한꺼번에 지우기
  - 남은 일 개수, 탭 제목
  - 목록 저장과 불러오기 (localStorage)
- 앱 구조
  - 루트 컴포넌트에 state 두기, 자식 컴포넌트는 props로 받기
  - 기능마다 쓰는 Hook (useState, useMemo, useEffect)
  - 목록 항목에 key 붙이기
- 2차 추가 기능 (5.9)
  - 들여다보기 패널, useState 지연 초기화, 순서 바꾸기, 연속 update 횟수 제한

### 2.2 제외

| 제외 항목                         | 이유                                                                                                                         |
| --------------------------------- | ---------------------------------------------------------------------------------------------------------------------------- |
| 할 일 글자 수정                   | 편집 중 상태가 늘어 요구사항이 가장 크게 늘어난다. 추가, 끝냄 표시, 삭제만으로 Hook과 Diff를 모두 보여 줄 수 있다.            |
| JSX                               | `h` 함수를 직접 부르는 코드로 "VNode를 직접 만든다"는 점을 보여 준다. 빌드 설정도 바꾸지 않는다. (6.1)                        |
| 서버 저장, 여러 기기 동기화       | 브라우저 하나의 localStorage에만 저장한다.                                                                                    |
| 여러 목록, 마감일, 우선순위       | Hook과 Diff를 보여 주는 데 필요하지 않다.                                                                                     |
| 페이지 꾸밈(디자인)의 세부 규칙   | 이 문서는 동작만 다룬다. 생김새는 설계에서 정한다.                                                                            |
| Phase 1 검증 페이지의 동작         | [phase1_requirement.md](phase1/phase1_requirement.md)에서 다룬다. 이 문서는 첫 화면의 링크만 다룬다.                          |

### 2.3 사용 규칙 (앱 코드가 지킨다)

> Phase 2 [앱 작성 규칙(FR-A01~A12)](phase2/function-component_requirement.md#54-앱-작성-규칙)을 그대로 따른다. 할 일 앱에서 특히 지킬 것은 다음과 같다.

- state 배열은 고치지 않고 새로 만들어 setState에 넘긴다. (예: `setTodos(ts => [...ts, todo])`. `todos.push(todo)`는 화면도 바뀌지 않고 useMemo와 useEffect도 바뀐 것을 알아채지 못한다.)
- 입력창은 `value`와 `onInput`을 함께 넘기는 제어 입력으로 쓴다. ([props 설계 경계 케이스](../design/phase2/props.md#경계-케이스))
- 지금 useState는 초깃값으로 함수를 넘기면 함수 자체를 state로 저장한다. 저장된 목록은 `useState(loadTodos())`처럼 값을 넘겨 불러온다. ([use-state 설계 "정하지 않은 것"](../design/phase2/use-state.md#정하지-않은-것))

## 3. 용어

> FunctionComponent, Hook, 렌더링 등 Phase 2 용어는 [function-component_requirement.md 3절](phase2/function-component_requirement.md#3-용어)을 따른다.

| 용어            | 뜻                                                                                                                                        |
| --------------- | ----------------------------------------------------------------------------------------------------------------------------------------- |
| 할 일           | 목록의 항목 하나. 겹치지 않는 `id`, 글자(`text`), 끝냈는지(`done`)를 가진다. (예: `{ id: 3, text: '우유 사기', done: false }`)             |
| 할 일 목록      | 할 일의 배열. 추가한 순서대로 들어 있다. 루트 컴포넌트의 state다.                                                                           |
| 남은 일         | `done`이 `false`인 할 일.                                                                                                                  |
| 끝낸 일         | `done`이 `true`인 할 일.                                                                                                                   |
| 필터            | 목록에 어떤 할 일을 보여 줄지 고르는 값. `전체`, `남은 일`, `끝낸 일` 중 하나다.                                                            |
| 보이는 목록     | 할 일 목록에서 필터에 맞는 할 일만 골라낸 배열. 화면의 목록은 이 배열로 그린다.                                                              |
| 입력값          | 할 일 입력창에 지금 들어 있는 글자. 루트 컴포넌트의 state다.                                                                                |
| 저장소          | 브라우저의 localStorage. 할 일 목록을 JSON 문자열로 저장한다.                                                                               |
| IME 조합 중     | 한글처럼 여러 키를 눌러 글자 하나를 만드는 입력기에서 글자가 아직 확정되지 않은 상태. 이때 누른 Enter는 글자 확정에 쓰인다.                   |

## 4. 동작 흐름

### 4.1 화면 구성

```text
App (루트: state를 모두 가짐)
├─ 입력 영역      입력창, 추가 버튼
├─ 필터 영역      전체 / 남은 일 / 끝낸 일 버튼
├─ 목록           할 일 항목 (체크박스, 글자, 삭제 버튼) × 보이는 목록 개수
│                 보이는 목록이 비면 안내 문구
└─ 아래 영역      남은 일 개수, 끝낸 일 지우기 버튼
```

자식 컴포넌트를 어떻게 나눌지, 각 컴포넌트가 받는 props는 설계에서 정한다. (#93)

### 4.2 기능과 Hook

| 기능                         | state (useState)          | 계산 (useMemo)                   | effect (useEffect)                       |
| ---------------------------- | ------------------------- | -------------------------------- | ---------------------------------------- |
| 추가, 끝냄 표시, 삭제, 끝낸 일 지우기 | 할 일 목록               | -                                | -                                        |
| 입력                         | 입력값                    | -                                | -                                        |
| 필터                         | 필터                      | 보이는 목록 (deps: 목록, 필터)    | -                                        |
| 남은 일 개수                 | -                         | 남은 일 개수 (deps: 목록)         | 탭 제목 바꾸기 (deps: 남은 일 개수)        |
| 저장                         | -                         | -                                | 저장소에 쓰기 (deps: 목록)                |

### 4.3 페이지 로드

1. 저장소에서 할 일 목록을 읽어 할 일 목록 state의 초깃값으로 쓴다. 없거나 읽을 수 없으면 빈 목록으로 시작한다.
2. 입력값은 빈 문자열, 필터는 `전체`로 시작한다.
3. `main.ts`가 FunctionComponent를 만들고 `mount()`를 한 번 부른다. ([FR-A12](phase2/function-component_requirement.md#54-앱-작성-규칙))
4. mount 뒤 effect가 실행되어 탭 제목을 남은 일 개수로 바꾸고 저장소에 목록을 쓴다.

### 4.4 사용자 동작 한 번

```text
입력·클릭 → 자식의 핸들러 → props로 받은 루트의 함수 → setState
  → update: App 다시 실행 (useMemo는 deps가 바뀐 것만 다시 계산)
  → Diff → Patch (바뀐 노드만)
  → effect (deps가 바뀐 것만 실행)
```

예: 입력창에 글자를 치면 입력값만 바뀐다. 보이는 목록과 남은 일 개수는 다시 계산하지 않고, 저장과 탭 제목 effect도 실행하지 않는다.

## 6. 설계로 넘기는 항목

### 6.1 결정된 항목

- 주제는 할 일 앱으로 한다.
  - 근거: 기능 하나를 쓸 때마다 useState, useMemo, useEffect, key Diff, 이벤트 props, 제어 입력 중 하나를 설명할 수 있다. 학습 정리와 발표에 맞다.
- JSX를 쓰지 않고 `h` 함수를 직접 부른다.
  - 근거: 컴포넌트 코드가 VNode를 만드는 과정을 그대로 보여 준다. 빌드 설정도 바꾸지 않는다.
- 페이지는 셋으로 나눈다. `index.html`은 첫 화면, `phase1.html`은 Phase 1 검증 페이지, `phase2.html`은 할 일 앱이다. 할 일 앱의 진입점은 `src/phase2/main.ts`다. (PR #136)
- useState 지연 초기화는 2차 구현이다. 1차에서는 `useState(loadTodos())`로 불러온다. 저장소 읽기는 가벼워서 렌더링마다 다시 읽어도 문제가 되지 않는다. (PR #137)
- 필터는 저장하지 않는다. 새로고침하면 `전체`로 돌아간다.
  - 근거: 저장할 값이 늘면 effect가 늘어 요구사항이 커진다. 발표에서 보여 줄 저장은 목록 하나로 충분하다.
- 새 할 일은 목록 맨 뒤에 넣는다. (FR-AD02)
- 빈 입력은 추가하지 않고, 추가 버튼을 비활성화해 알린다. 오류 문구는 보여 주지 않는다. (FR-AD07, AD08)
- IME 조합 중의 Enter는 무시한다. (FR-AD06)
  - 근거: 한글을 입력하고 Enter를 누르면 조합 확정과 입력 완료 두 번 `keydown`이 일어나, 처리하지 않으면 같은 할 일이 두 번 추가된다.

## 7. 추후 논의

- 할 일 글자 수정: 2.2에서 뺐다. 시간이 남으면 2차 추가 기능으로 더할지 정한다.
- 이벤트 핸들러의 배칭: 추가할 때 `setTodos`와 `setText`를 함께 불러 update가 두 번 일어난다. 결과 화면은 같다. [FunctionComponent 설계 "정하지 않은 것"](../design/phase2/function-component.md#정하지-않은-것)의 배칭과 함께 정한다.
- 첫 화면(`index.html`)의 디자인: 지금은 링크 두 개만 있다. 발표용으로 꾸밀지 정한다.
- Phase 1 검증 페이지에서 첫 화면으로 돌아가는 링크: Phase 1 요구사항에 더할지 정한다.
