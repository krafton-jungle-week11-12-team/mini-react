# [스킬 제목]

입력: `$ARGUMENTS`

## 0. 입력 확인

<!-- 인자를 어떻게 읽는지, 비었거나 잘못됐을 때 어떻게 하는지 써요. -->

- 첫 단어는 [인자 의미]예요. (예: [실제 값]) [다른 형식으로 오면 어떻게 읽는지]
- 둘째 단어부터는 [인자 의미]예요. 없으면 [기본 동작]을 해요.
- [인자]가 비어 있거나 [대상 경로]가 없으면, [고를 수 있는 목록]을 보여 주고 AskUserQuestion으로 물어요. 추측해서 진행하지 않아요.

## 1. [시작 전 확인할 것]

<!--
작업을 시작해도 되는지 먼저 확인해요. (예: 요구사항 문서가 완성됐는지)
확인 항목은 번호 목록으로 쓰고, 기계적으로 확인할 수 있게 구체적인 기준(주석, 자리표시자, 필수 섹션 등)을 적어요.
-->

[대상]마다 아래를 확인해요.

1. **[항목]**: [통과 기준]
2. **[항목]**: [통과 기준]

결과는 아래 형식으로 보여 줘요.

| [대상] | 결과 (통과 / 실패) | 남은 항목 (줄 번호와 내용) |
| ------ | ------------------ | -------------------------- |

- 모두 통과면 2단계로 넘어가요.
- 하나라도 실패면 멈추고 AskUserQuestion으로 물어요. 실패한 [대상]을 대신 고치지 않아요.
  - **중단** (추천): [사용자가 먼저 할 일]을 하고 다시 실행해요.
  - **[대안]**: [대안을 고르면 어떻게 진행하는지]

## 2. 읽을 문서

<!-- 작업 전에 반드시 읽을 파일을 순서대로 써요. 형식의 기준이 되는 템플릿과 문장 기준은 꼭 넣어요. -->

작성 전에 아래를 모두 읽어요.

1. `[경로]` — [왜 읽는지]
2. `[템플릿 경로]` — [결과물 형식]. 4단계 "형식 지키기"대로 이 형식을 그대로 따라요.
3. `docs/technical-writing-principles.md` — 문장 기준 (`.claude/rules/docs-writing.md`가 가리키는 원칙)

## 3. [작업 나누기 / 계획 확인]

<!-- 무엇을 만들거나 고칠지 표로 보여 주고, 쓰기 전에 사용자 확인을 받아요. -->

- [나누는 기준]
- 쓰기 전에 아래 표를 사용자에게 보여 주고 확인을 받아요. 이미 있는 파일을 고치는 경우도 표에 적어요.

| [결과물 경로] | [대상] | [다루는 범위] | 새로 작성 / 수정 |
| ------------- | ------ | ------------- | ---------------- |

## 4. [작성]

### 형식 지키기

<!-- 결과물이 따라야 할 형식을 템플릿 기준으로 써요. 제목, 머리 정보, 섹션 이름과 순서, 섹션 안 표의 열 이름을 구체적으로 적어요. -->

새 [결과물]은 `[템플릿 경로]`를 복사해서 시작하고, 형식을 바꾸지 않고 칸만 채워요.

- **[형식 항목]**: [규칙]
- **주석**: 템플릿의 안내 주석은 다 쓴 뒤 모두 지워요.
- **자리표시자**: 템플릿 그대로인 칸을 남기지 않아요. 예외는 [예외 규칙]뿐이에요.

### 내용 규칙

<!-- 내용을 채울 때 지킬 것을 써요. 없는 값을 지어내지 않기, 다른 문서를 대신 고치지 않기처럼 경계를 분명히 해요. -->

- [규칙]
- [사용자 결정이 필요한 경우 어떻게 하는지]

## 5. 검증

<!-- 다 쓴 뒤 확인할 항목을 번호 목록으로 써요. grep, ls처럼 확인 방법이 있으면 함께 적어요. -->

[검증 대상 범위]를 대상으로 아래를 확인해요.

1. **[항목]**: [통과 기준]
2. **[항목]**: [통과 기준]
3. **문서 검수**: 결과를 주기 전에 `.claude/skills/doc-check/SKILL.md`를 읽고, 이번에 쓰거나 고친 문서 경로를 입력으로 그 절차대로 검수해요. 쓰거나 고친 문서가 없으면 건너뛰고 보고에 "검수할 문서 없음"이라고 적어요.
