# ADR-008: Diff 결과 표시는 Diff와 분리하고, 화면 표시는 브라우저에 물어 판단한다

- 상태: 제안됨
- 관리 범위: mini-react 저장소 (docs/adr)

## 개요

Patch 후 바뀐 부분을 어떻게 보여줄지에 대한 결정이에요. 이 글을 읽으면 공백·주석처럼 화면에 안 보이는 변경을 로그와 하이라이트에서 각각 어떻게 다루는지, 왜 `innerText`로 보이는지 판단하는지 알 수 있어요.

## 맥락

ADR-007에 따라 Diff는 공백·주석 변경도 잡아요. 하지만 이런 변경은 화면에 안 보일 때가 많아 하이라이트할 자리가 없어요. 공백이 보이는지는 태그 종류, 위치, CSS `white-space`에 따라 달라요.

## 고려한 선택지

### 선택지 A: 공백 규칙을 직접 구현해 거른다

- 장점: 외부 API에 의존하지 않아요.
- 단점: 블록 사이, 줄 앞뒤, 이웃 노드 합치기, `pre`·`&nbsp;` 예외를 모두 맞춰야 해요.

### 선택지 B: `innerText`로 브라우저에 묻는다

- 장점: 브라우저가 공백 규칙을 그대로 적용해 줘요.
- 단점: 읽을 때 Reflow가 일어나요.

## 결정

변경 표시는 Diff와 분리하고, 텍스트 변경이 보이는지는 `innerText`로 판단한다.

| Diff 결과 | 변경 로그 | 화면 하이라이트 |
|---|---|---|
| 요소·속성 변경 | 표시 | 표시 |
| 텍스트 변경 (공백 포함) | 표시 | 부모 `innerText`가 바뀌었을 때만 |
| 주석 변경 | 표시 | 표시 안 함 |

1. 로그에서 공백은 `·`, 줄바꿈은 `↵`로 보여준다.
2. 하이라이트는 `element.animate()`로 한다. 실제 영역 DOM에 속성을 붙이지 않는다.

## 근거

브라우저 규칙을 다시 만드는 것보다 브라우저에 묻는 게 정확해요. Reflow는 Patch 때 한 번이라 감수해요.

## 예상되는 결과

- 긍정적 영향: 안 보이는 변경도 로그로 확인할 수 있어요.
- 부정적 영향 / 리스크: 화면에 렌더링되지 않은 요소(`display: none`)는 `innerText`로 판단할 수 없어요.
