## 개요

Patch는 Diff 결과를 받아 실제 영역의 DOM에서 바뀐 노드만 고쳐요. 이 문서를 읽으면 Diff 결과를 DOM API 호출로 바꾸는 방법과, 바뀌지 않은 노드를 그대로 두는 방법을 알고 Patch를 구현할 수 있어요.

## 다루는 요구사항

| ID     | 요구사항 요약                                                         | 이 문서에서 다루는 곳 |
| ------ | --------------------------------------------------------------------- | --------------------- |
| FR-E04 | 바뀐 노드만 실제 DOM에 반영하고 전체를 다시 그리지 않아요             | 동작 방식             |
| FR-E09 | 빈 문자열로 Patch하면 실제 영역의 모든 노드를 삭제해요                | 경계 케이스           |
| FR-W14 | 바뀐 노드에 대해서만 DOM API를 호출하고 나머지 노드는 그대로 둬요     | 동작 방식             |
| FR-W15 | Patch가 끝나면 실제 영역과 테스트 영역의 렌더링 결과가 같아요         | 검증 방법             |

## 위치와 흐름

```text
Diff 결과 + 실제 영역 컨테이너 ──▶ Patch ──▶ 고쳐진 실제 영역 DOM ──▶ 변경 표시
```

- 입력을 주는 곳: 검증 페이지(Patch 버튼. 요구사항 4.2의 5단계), 새 노드가 필요하면 [Virtual DOM 변환](vdom.md)
- 출력을 받는 곳: 실제 영역 DOM, [변경 표시](change-highlight.md)

## 설계 결정

| 결정                                            | 이유                                                          | 관련 ADR                              |
| ----------------------------------------------- | ------------------------------------------------------------- | ------------------------------------- |
| 새 노드는 Virtual DOM → DOM 변환으로 만든다     | 렌더링 결과는 파싱한 DOM으로 만들고, 변환은 Patch에서만 써요  | [ADR-004](../adr/ADR-004.md)          |
| 실제 영역 DOM에 강조용 속성을 붙이지 않는다     | 강조 표시가 두 영역 비교(FR-W15)에 영향을 주지 않아야 해요    | [ADR-008](../adr/ADR-008.md) (제안됨) |

## 경계 케이스

| 경우                          | 입력 예시 (이전 → 새)                                  | 기대 동작                                       | 관련 요구사항 |
| ----------------------------- | ------------------------------------------------------ | ----------------------------------------------- | ------------- |
| 모두 삭제                     | 샘플 HTML 코드 → 빈 문자열                             | 실제 영역에 노드가 하나도 남지 않아요           | FR-E09        |
| 한 부모에서 여러 자식 삭제    | `<li>A</li><li>B</li><li>C</li>` → `<li>B</li>`        | 남은 노드가 올바른 위치에 있어요                | FR-W14        |
| 바뀌지 않은 형제 노드         | 샘플에서 `h1` 텍스트만 변경                            | `ul`, `button`은 같은 DOM 객체(`===`)로 남아요  | FR-E04        |
| 교체                          | `<p>A</p>` → `<div>A</div>`                            | 같은 위치에 새 노드가 들어가요                  | FR-E04        |

## 검증 방법

- 단위 테스트
  - FR-E04, W14: Patch 전후로 바뀌지 않은 노드가 같은 DOM 객체(`===`)로 남는지 확인해요.
  - FR-E09: 빈 문자열로 Patch한 뒤 실제 영역에 노드가 없는지 확인해요.
  - FR-W15: 강조 표시를 뺀 두 영역의 DOM을 각각 Virtual DOM 트리로 변환해 같은지 확인해요. 다르면 Diff가 노드를 놓친 것이에요.
- 검증 페이지: Patch 버튼을 누른 뒤 두 영역이 같게 보이는지 확인해요.

## 정하지 않은 것

- Patch 도중 오류가 나서 실제 영역이 일부만 바뀐 경우의 처리: 요구사항 6절.
- 변경 표시에 바뀐 DOM 노드를 넘기는 방법(Patch가 돌려줄지, 변경 표시가 Diff 결과의 위치로 다시 찾을지): [변경 표시 설계](change-highlight.md)와 함께 정해요.
- 뒤로가기, 앞으로가기 때 실제 영역 복원에 Patch를 쓸지: 요구사항 4.3, 6절. [검증 페이지 설계](page.md)와 함께 정해요.
