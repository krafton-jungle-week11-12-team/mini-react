# Diff 설계

- 상태: 작성 중
- 작성자: [이름]
- 관련 이슈: #12

## 개요

Diff는 Virtual DOM 트리 두 개를 비교해 노드 추가, 삭제, 교체, 속성 변경, 텍스트 변경을 찾아요. 이 문서를 읽으면 Diff 결과의 형태와 비교 규칙을 알고 Diff를 구현할 수 있어요.

## 다루는 요구사항

| ID     | 요구사항 요약                                                       | 이 문서에서 다루는 곳 |
| ------ | ------------------------------------------------------------------- | --------------------- |
| FR-E03 | 두 트리를 비교해 추가, 삭제, 교체, 속성 변경, 텍스트 변경을 찾아요 | 동작 방식             |

## 위치와 흐름

```text
현재 기록의 vdom + 새 Virtual DOM 트리 ──▶ Diff ──▶ Diff 결과 ──▶ Patch, 변경 표시
```

- 입력을 주는 곳: 검증 페이지(Patch 버튼. 요구사항 4.2의 4단계, FR-W13)
- 출력을 받는 곳: [Patch](patch.md), [변경 표시](change-highlight.md)

## 설계 결정

| 결정                                          | 이유                                                               | 관련 ADR                              |
| --------------------------------------------- | ------------------------------------------------------------------ | ------------------------------------- |
| 이전 트리로 현재 기록의 `vdom`을 받는다       | 한 기록의 Patch 후가 다음 기록의 Patch 전이라 따로 저장하지 않아요 | [ADR-006](../adr/ADR-006.md)          |
| 공백·주석 노드를 포함해 모든 노드를 비교한다  | 정확성을 먼저 택해요                                               | [ADR-007](../adr/ADR-007.md) |
| 화면에 보이는지는 Diff 결과에 넣지 않는다     | 변경 표시는 Diff와 분리해요                                        | [ADR-008](../adr/ADR-008.md) |
| 두 루트 목록(`VNode[]`)을 받아 컨테이너의 자식 목록처럼 비교한다 | [Virtual DOM 변환](vdom.md)이 컨테이너를 빼고 자식 목록을 돌려줘요 | [ADR-005](../adr/ADR-005.md) |
| `kind`나 `tag`, `ns`가 다르면 교체로 본다 | 다른 종류의 노드는 고쳐 쓸 수 없어요 | - |

## 경계 케이스

| 경우                    | 입력 예시 (이전 → 새)                           | 기대 동작                    | 관련 요구사항 |
| ----------------------- | ----------------------------------------------- | ---------------------------- | ------------- |
| 노드 추가               | `<li>A</li>` → `<li>A</li><li>B</li>`           | 추가 1개                     | FR-E03        |
| 노드 삭제               | `<li>A</li><li>B</li>` → `<li>A</li>`           | 삭제 1개                     | FR-E03        |
| 교체 (태그가 다름)      | `<p>A</p>` → `<div>A</div>`                     | 교체 1개                     | FR-E03        |
| 교체 (노드 종류가 다름) | `A` → `<b>A</b>`                                | 교체 1개                     | FR-E03        |
| 교체 (텍스트 → 주석)    | `A` → `<!--A-->`                                | 교체 1개                     | FR-E03        |
| 주석 내용 변경          | `<!-- a -->` → `<!-- b -->`                     | 텍스트 변경 1개 (`text` 비교) | FR-E03, W26   |
| 공백만 변경             | `<li>A</li>` → `<li> A</li>`                    | 텍스트 변경 1개              | FR-W25        |
| 속성 변경               | `<h1 class="a">` → `<h1 class="b">`             | 속성 변경 1개                | FR-E03        |
| 텍스트 변경             | `<li>A</li>` → `<li>B</li>`                     | 텍스트 변경 1개              | FR-E03        |
| 순서 바뀜               | `<li>A</li><li>B</li>` → `<li>B</li><li>A</li>` | 자식 비교 방식에 따라 정해요 | 요구사항 6절  |
| 모두 삭제               | 샘플 HTML 코드 → 빈 문자열                      | 루트의 자식이 모두 삭제돼요  | FR-E09        |
| 바뀐 내용 없음          | 같은 트리                                       | 빈 결과                      | FR-W28        |

## 검증 방법

- 단위 테스트: 위 다섯 가지 변경마다 테스트 케이스를 두고, Diff 결과에 해당 변경만 담기는지 확인해요(FR-E03).
- 검증 페이지: Diff 결과를 직접 보여 주는 화면은 2차 기능(FR-X04)이에요. 기본 기능에서는 Patch 후 두 영역이 같은지(FR-W15)로 간접 확인해요.

## 정하지 않은 것

- Diff 결과 타입과 노드 위치 표현 방식: [Patch](patch.md), [변경 표시](change-highlight.md)와 함께 정해요.
- 자식 비교 방식(key 없이 인덱스 기준, 순서가 바뀌면 삭제 + 추가로 볼지): 요구사항 6절.
