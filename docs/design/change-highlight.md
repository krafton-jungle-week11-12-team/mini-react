# 변경 표시 설계

- 상태: 작성 중
- 작성자: [이름]
- 관련 이슈: #12

## 개요

변경 표시는 Patch로 바뀐 부분을 실제 영역에서 강조해 보여 줘요. 이 문서를 읽으면 Diff 결과 중 무엇을 화면에 강조하고, 강조가 두 영역 비교에 영향을 주지 않게 하는 방법을 알 수 있어요.

## 다루는 요구사항

| ID     | 요구사항 요약                                                       | 이 문서에서 다루는 곳 |
| ------ | ------------------------------------------------------------------- | --------------------- |
| FR-W16 | Patch하면 실제 영역에서 바뀐 노드를 강조 표시해요                   | 동작 방식             |
| FR-W27 | 강조 표시가 두 영역 비교(FR-W15)에 영향을 주지 않아요               | 설계 결정             |
| FR-X04 | (2차 기능) 바뀐 노드와 변경 종류를 보여 줘요                        | 동작 방식             |

## 위치와 흐름

```text
Diff 결과 + Patch 후 실제 영역 ──▶ 변경 표시 ──▶ 화면 하이라이트 (2차: 변경 로그)
```

- 입력을 주는 곳: 검증 페이지(Patch 버튼. 요구사항 4.2의 5단계), [Diff](diff.md) 결과, [Patch](patch.md)가 고친 노드
- 출력을 받는 곳: 화면

## 설계 결정

| 결정                                                                   | 이유                                                       | 관련 ADR                              |
| ---------------------------------------------------------------------- | ---------------------------------------------------------- | ------------------------------------- |
| 변경 표시는 Diff와 분리한다                                            | 화면에 보이는지는 Diff가 아니라 표시 단계에서 판단해요     | [ADR-008](../adr/ADR-008.md) (제안됨) |
| 요소·속성 변경은 하이라이트한다                                        | 항상 화면에 드러나요                                       | [ADR-008](../adr/ADR-008.md) (제안됨) |
| 텍스트 변경은 부모의 `innerText`가 바뀌었을 때만 하이라이트한다         | 공백이 보이는지는 브라우저에 묻는 게 정확해요              | [ADR-008](../adr/ADR-008.md) (제안됨) |
| 주석 변경은 하이라이트하지 않는다                                      | 화면에 보이지 않아요                                       | [ADR-008](../adr/ADR-008.md) (제안됨) |
| 하이라이트는 `element.animate()`로 하고 DOM에 속성을 붙이지 않는다      | 강조가 두 영역 비교에 영향을 주지 않아요(FR-W27)           | [ADR-008](../adr/ADR-008.md) (제안됨) |
| 변경 로그에서 공백은 `·`, 줄바꿈은 `↵`로 보여 준다                      | 화면에 안 보이는 변경도 로그로 확인할 수 있어요            | [ADR-008](../adr/ADR-008.md) (제안됨) |

## 경계 케이스

| 경우                         | 입력 예시 (이전 → 새)                       | 기대 동작                                       | 관련 요구사항 |
| ---------------------------- | ------------------------------------------- | ----------------------------------------------- | ------------- |
| 보이지 않는 공백 변경        | `<li>A</li>` → `<li> A</li>`                | 하이라이트하지 않아요. 로그에는 남아요          | FR-W16        |
| `<pre>` 안의 공백 변경       | `<pre>A</pre>` → `<pre> A</pre>`            | `innerText`가 바뀌어 하이라이트해요             | FR-W16        |
| 주석 변경                    | `<!-- a -->` → `<!-- b -->`                 | 하이라이트하지 않아요. 로그에는 남아요          | FR-W16        |
| 삭제된 노드                  | `<li>A</li><li>B</li>` → `<li>A</li>`       | [정하기] 하이라이트할 노드가 화면에 없어요      | FR-W16        |
| 화면에 렌더링되지 않은 요소  | `display: none` 요소 안의 텍스트 변경       | `innerText`로 판단할 수 없어요                  | FR-W16        |

## 검증 방법

- 단위 테스트: FR-W27은 하이라이트 중에도 FR-W15 비교(두 영역 Virtual DOM 트리 비교)가 통과하는지 확인해요.
- 검증 페이지: 위 경계 케이스마다 Patch해서 바뀐 노드만 강조되는지 확인해요(FR-W16).

## 정하지 않은 것

- ADR-008 승인 여부: 승인되면 FR-W16이 "화면에 보이는 변경만 강조 표시한다"로 바뀌어요. 변경 로그를 이번 범위에 넣을지도 이때 정해요.
- 바뀐 DOM 노드를 받는 방법(Patch가 돌려줄지, Diff 결과의 위치로 다시 찾을지): [Patch 설계](patch.md)와 함께 정해요.
- `innerText`를 비교하려면 Patch 전 값을 읽어 둬야 해요. 언제, 어디서 읽을지 정해요.
- 삭제된 노드를 어떻게 표시할지 정해요.
