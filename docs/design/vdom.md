## 개요

Virtual DOM 변환은 영역 컨테이너 아래의 DOM 트리를 Virtual DOM 트리로 바꾸고, Virtual DOM 노드를 다시 DOM 노드로 바꿔요. 이 문서를 읽으면 모든 모듈이 주고받는 `VNode` 타입과 두 변환 함수의 동작을 알고 구현할 수 있어요.

## 다루는 요구사항

| ID     | 요구사항 요약                                                   | 이 문서에서 다루는 곳 |
| ------ | --------------------------------------------------------------- | --------------------- |
| FR-E01 | DOM 트리를 태그, 속성, 자식(텍스트 포함)을 가진 트리로 변환해요 | 동작 방식             |
| FR-E02 | Virtual DOM 트리로 다시 만든 DOM은 원래 DOM과 같아요            | 동작 방식, 검증 방법  |
| FR-E05 | HTML 문자열이 아니라 브라우저가 파싱한 DOM 트리를 변환해요      | 인터페이스            |
| FR-E06 | 공백과 줄바꿈만 있는 텍스트 노드는 넣지 않아요                  | 경계 케이스           |
| FR-E07 | 주석 노드는 넣지 않아요                                         | 경계 케이스           |
| FR-E08 | 빈 문자열을 포함한 모든 파싱 결과를 유효성 검사 없이 변환해요   | 경계 케이스           |

## 위치와 흐름

```text
영역 컨테이너의 DOM 트리 ──(DOM → Virtual DOM)──▶ Virtual DOM 트리 ──▶ Diff, State History
Virtual DOM 노드 ──(Virtual DOM → DOM)──▶ 새 DOM 노드 ──▶ Patch
```

- 입력을 주는 곳: 검증 페이지(로드 때 실제 영역, Patch 때 테스트 영역. 요구사항 4.1의 4단계, 4.2의 3단계), Patch(새 노드가 필요할 때)
- 출력을 받는 곳: [Diff](diff.md), [State History](history.md), [Patch](patch.md)

## 설계 결정

| 결정                                                       | 이유                                                            | 관련 ADR                                 |
| ---------------------------------------------------------- | --------------------------------------------------------------- | ---------------------------------------- |
| 변환은 영역 컨테이너의 자식부터 시작한다                   | 텍스트만 있거나 루트가 여러 개인 입력도 그대로 처리할 수 있어요 | [ADR-005](../adr/ADR-005.md)             |
| 유효성 검사를 하지 않는다                                  | 두 영역 모두 브라우저가 파싱하며 똑같이 보정해요                | [ADR-005](../adr/ADR-005.md)             |
| Virtual DOM → DOM 변환은 Patch가 새 노드를 만들 때만 쓴다 | 렌더링 결과는 항상 파싱한 DOM으로 만들어요                      | [ADR-004](../adr/ADR-004.md)             |
| 공백·줄바꿈·주석 노드를 모두 넣는다                        | 노드 번호가 어긋나면 Patch가 엉뚱한 노드를 고쳐요               | [ADR-007](../adr/ADR-007.md) (제안됨)    |

## 경계 케이스

| 경우                     | 입력 예시                             | 기대 동작                                                   | 관련 요구사항 |
| ------------------------ | ------------------------------------- | ----------------------------------------------------------- | ------------- |
| 브라우저가 태그를 보충함 | `<table><tr><td>A</td></tr></table>`  | 트리에 `tbody`가 들어 있어요                                | FR-E05        |
| 공백만 있는 텍스트 노드  | `<ul>`와 `<li>A</li>` 사이 줄바꿈     | ADR-007 승인 전: 넣지 않아요. 승인 후: 텍스트 노드로 넣어요 | FR-E06        |
| 주석 노드                | `<div><!-- 메모 --><p>A</p></div>`    | ADR-007 승인 전: 넣지 않아요. 승인 후: 주석 노드로 넣어요   | FR-E07        |
| 빈 문자열                | (빈 문자열)                           | 자식이 없는 결과를 오류 없이 돌려줘요                       | FR-E08        |
| 닫히지 않은 태그         | `<ul><li>A`                           | 브라우저가 보정한 결과를 그대로 변환해요                    | FR-E08        |
| 텍스트만, 루트 여러 개   | `안녕`, `<p>A</p><p>B</p>`            | 그대로 변환해요                                             | FR-E08        |

## 검증 방법

- 단위 테스트
  - FR-E01: 샘플 HTML 코드를 변환해 노드마다 태그, 속성, 텍스트, 자식 순서가 같은지 확인해요.
  - FR-E02: DOM → Virtual DOM → DOM 왕복 결과를 `isEqualNode`로 원래 DOM과 비교해요.
  - FR-E05: `<table>` 예시에서 `tbody`가 있는지 확인해요.
  - FR-E08: 빈 문자열, 닫히지 않은 태그, 잘못된 중첩에서 오류가 없는지 확인해요.
- 검증 페이지: 이 모듈만 따로 확인하는 화면은 없어요. 로드 직후 첫 기록의 변환 결과(FR-W03)는 [검증 페이지 설계](page.md)에서 확인해요.

## 정하지 않은 것

- ADR-007 승인 여부: 승인되면 FR-E02, E06, E07이 바뀌어요. FR-E02 확인 방법에서 공백·주석 노드를 빼는 단계가 없어져요.
- 노드 종류(요소, 텍스트, 주석)를 `VNode`에서 구분하는 방식: 자료구조를 쓸 때 정해요.
- 트리 순회 방식(재귀 / 반복문 스택 / Fiber): 요구사항 6절. ADR로 기록해요.
- Virtual DOM → DOM으로 만든 `<script>`의 실행 여부: 요구사항 7절 스크립트 실행 정책과 함께 정해요.
