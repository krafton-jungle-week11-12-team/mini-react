# ADR-007: 공백·주석 노드는 Virtual DOM에 모두 넣는다

- 상태: 승인됨
- 관리 범위: mini-react 저장소 (docs/adr)

## 개요

공백·줄바꿈·주석 노드를 Virtual DOM에서 어떻게 다룰지에 대한 결정이에요. 이 글을 읽으면 왜 이 노드들을 빼지 않고 모두 넣는지, 그래서 Patch 버튼이 언제 켜지는지 알 수 있어요.

## 맥락

브라우저는 공백·줄바꿈·주석도 DOM 노드로 만들지만, 화면에는 보이지 않을 때가 많아요. 이 노드를 Virtual DOM에서 빼면 자식 번호가 실제 DOM과 어긋나요. 예를 들어 Diff가 "첫 번째 자식을 바꿔라"라고 해도 실제 DOM의 첫 번째 자식은 줄바꿈 텍스트 노드라서 엉뚱한 노드가 바뀌어요.

## 고려한 선택지

### 선택지 A: Virtual DOM에서 뺀다

- 장점: 들여쓰기만 바꾼 변경이 Diff에 잡히지 않아요.
- 단점: 자식 번호가 어긋나 Patch가 엉뚱한 노드를 고쳐요. 인라인 요소 사이 띄어쓰기와 `<pre>` 공백이 사라져요.

### 선택지 B: 모두 넣는다

- 장점: 자식 번호가 1:1로 맞고 화면을 정확히 재현해요.
- 단점: 들여쓰기나 주석만 바꿔도 Patch 버튼이 켜져요.

## 결정

공백·줄바꿈·주석 노드를 모두 Virtual DOM에 넣는다. Diff는 모든 노드를 비교한다.

1. 공백·줄바꿈·주석 변경도 바뀐 내용으로 본다.
2. Patch 버튼은 Diff에 변경이 있으면 켜고, 없으면 끈다(FR-W10). 주석만 따로 무시하는 판단은 두지 않는다.

## 근거

번호가 어긋나면 결과가 틀리지만, Patch 버튼이 켜지는 건 불편함일 뿐이에요. 정확성을 먼저 택해요.

주석만 무시하려면 Diff와 다른 비교 함수가 하나 더 필요해요. 그러면 버튼은 꺼져 있는데 Diff에는 변경이 있는 어긋남도 생겨요. 버튼 판단을 Diff 결과와 같게 두면 이런 어긋남이 없어요.

## 예상되는 결과

- 긍정적 영향: Patch 위치가 어긋나지 않아요. 버튼 상태와 Diff 결과가 항상 같아요.
- 부정적 영향 / 리스크: 들여쓰기나 주석만 바꿔도 Patch 버튼이 켜져요. 이런 변경은 화면에 보이지 않을 수 있어서, 표시 방법은 [ADR-008](ADR-008.md)에서 다뤄요.
