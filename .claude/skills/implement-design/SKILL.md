# 설계 기반 최종 구현

입력: `$ARGUMENTS`

이 스킬이 고치는 파일은 테스트가 아닌 `src/` 코드예요. `src/**/*.test.ts`와 ADR, 요구사항, 설계 문서는 읽고 보고만 해요. 워크플로우는 `.claude/skills/README.md`의 "쓰는 순서" 절을 봐요.

## 0. 입력 확인

- 첫 단어는 Phase예요. `.claude/skills/README.md`의 "Phase 인자" 절대로 읽어요.
- 둘째 단어부터는 설계 문서 경로예요. (예: `docs/design/phase2/use-state.md`) 그 설계 문서의 모듈만 대상으로 해요. 없으면 그 Phase의 설계 문서 전체를 대상으로 해요.
- 준 경로에 파일이 없으면 멈추고 알려요.

## 1. 시작 전 확인

1. **테스트**: `npm test`로 전체 테스트를 돌려요. 실패가 있으면 멈추고 `/implement-tc`를 먼저 돌리라고 안내해요. 이 스킬은 통과한 테스트를 지키는 것이 전제예요.
2. **문서**: 이 Phase의 설계 문서가 하나 이상 있어요. 없으면 멈추고 `/design-doc`을 먼저 돌리라고 안내해요.

## 2. 읽을 문서

구현 전에 아래를 모두 읽어요.

1. `docs/adr/` — 상태가 "승인됨", "제안됨", "기각됨"인 ADR 중 이 Phase 요구사항이나 설계 문서가 가리키는 것
2. `docs/requirements/<phase>/` 아래 요구사항 문서 전부 — 2절 범위(포함, 제외), 4절 동작 흐름, 5절 기능 요구사항, 6.1 결정된 항목
3. 대상 설계 문서 전부와, 이어받는 앞 Phase 설계 문서 — 자료구조, 인터페이스, 동작 방식, 설계 결정, 경계 케이스, 정하지 않은 것
4. 대상 모듈의 `src/` 코드와 테스트 파일

## 3. 계획 확인

### 차이 찾기

문서와 구현을 비교해 다른 곳을 모두 찾아요.

- **ADR**: 승인된 ADR의 결정대로 구현했어요. 기각된 ADR의 선택지를 따르지 않았어요.
- **요구사항**: 비고가 "삭제됨"이 아닌 모든 요구사항 ID가 구현됐어요. 테스트가 없는 요구사항(검증 페이지 동작 등)도 봐요. 6.1 결정된 항목대로예요.
- **범위**: 요구사항 2.2 "제외"에 있는 기능을 구현하지 않았어요. 2차 기능을 기본 기능처럼 넣지 않았어요.
- **설계**: 타입 이름과 속성, 함수 시그니처, 동작 순서, 설계 결정, 경계 케이스가 설계 문서와 같아요.
- **1차 구현 흔적**: 테스트만 통과시키려고 넣은 임시 코드, 하드코딩, 쓰이지 않는 코드를 찾아요.

### 충돌과 미정 항목

- 문서끼리 다르면 "승인된 ADR → 요구사항 → 설계" 순서로 따라요. 다만 충돌을 찾으면 고치지 않고 표에 따로 적어 AskUserQuestion으로 어느 쪽을 따를지 물어요.
- "제안됨" ADR에 걸린 요구사항(비고 `ADR-<번호> 승인 시 수정`)은 현재 요구사항 본문을 따를지 물어요.
- 구현하려면 설계 문서 "정하지 않은 것"을 정해야 하면, 혼자 정하지 않고 물어요.

마지막으로 고칠 순서를 정해 보여 주고 확인을 받아요. 다른 모듈이 의존하는 타입과 함수부터 해요.

## 4. 구현

### 지킬 것

- `.claude/skills/implement-tc/SKILL.md` 4단계 "지킬 것"의 테스트 규칙을 따라요. 테스트 파일은 고치지 않아요.
- 설계대로 고치면 테스트가 깨지는 곳은 고치지 않고 멈춰서 AskUserQuestion으로 물어요. 설계와 테스트가 어긋난 곳이에요.
  - **테스트를 지키고 설계와 다르게 둠** (추천): 구현은 그대로 두고, 차이를 보고에 적어요.
  - **이 차이 건너뛰기**: 다음 묶음으로 넘어가요. 테스트나 설계를 고치는 일은 사용자나 `/make-testcase`, `/design-doc`이 해요.
- 앞 Phase의 타입과 함수를 바꿔야 하면 멈추고 물어요. 앞 Phase 테스트가 깨지지 않아야 해요.
- 같은 모듈의 기존 코드 관례(파일 위치, export 방식, 주석 언어)를 따라요.

### 순서

`implement-tc` 4단계 "순서"대로 묶음마다 고치고 `npm test` 전체를 다시 돌려요. 깨진 테스트가 있으면 다음 묶음으로 넘어가지 않아요.

## 5. 검증

이 스킬이 한 일만 확인하고, 테스트·타입 검사·빌드·검증 페이지는 마지막의 `test-final`에서 확인해요.

1. **테스트 파일**: `git diff --stat`으로 `*.test.ts`가 바뀌지 않았는지 확인해요.
2. **차이 다시 보기**: 3단계 차이 표를 다시 확인해, 남은 차이마다 이유(충돌, 미정, 건너뜀)가 있어요.
3. **문서 검수**: 이 스킬은 문서를 쓰지 않아요. 보고에 "검수할 문서 없음"이라고 적어요.
4. **최종 검증**: `.claude/skills/test-final/SKILL.md`를 읽고 `<phase>` 입력으로 그 절차를 따라요. `test-final`이 문제를 찾으면, 이번에 고친 구현 코드의 문제는 고치고 `test-final`을 다시 따라요.

- 이번에 고친 구현 코드의 문제는 바로 고치고 다시 검증해요.
- 테스트, ADR, 요구사항, 설계 문서를 고쳐야 하는 문제는 고치지 않고 보고만 해요.
